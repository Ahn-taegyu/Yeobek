# 문제

관람 질문의 근거 선택(`src/lib/ai/context.ts`의 `selectEvidence`)은 현재 공개본의 승인 근거 가운데 최대 12개·8,000자를 모델에 보낸다. 기존 방식은 질문을 띄어쓰기로 자른 어절이 본문에 **그대로** 들어 있는 개수만 셌다.

- “판화도”, “연작은”처럼 조사가 붙은 어절은 본문의 “판화를”, “연작 여섯 점”과 일치하지 않았다.
- “해바라기”, “작품”처럼 거의 모든 발췌에 있는 단어와 질문이 묻는 드문 사실이 같은 1점이었다.
- [RES-012](visitor-evidence-abstention.md)의 반 고흐 시험은 작품당 근거가 16개였지만 직접 근거가 12개 안에 들어가 누락이 드러나지 않았다.

# 변경

1. 질문의 한글 어절마다 끝의 조사·어미 하나를 떼되 2음절 이상을 남긴다. 예: 마을은→마을, 창밖에서→창밖, 판화도→판화.
2. “무엇·어떻게·어디·누가·얼마·기록”처럼 질문 형식만 나타내는 말은 제외한다.
3. 어간이 본문에 부분 문자열로 들어 있으면 그 어간의 **이번 요청 후보 안 희소도(IDF)**를 더한다. 본문 길이로 나누지 않으므로 짧은 안내문이 긴 직접 근거를 앞지르지 않는다.
4. 같은 점수면 기존처럼 작품 범위 → 서버가 준 순서를 유지한다. 발췌를 자르지 않고 12개·8,000자 예산도 그대로다.

처음에는 한글 2글자 조각을 더한 BM25(길이 보정 포함)를 시도했다. 합성 세트에서는 16/16이었으나 반 고흐 기록에서 짧은 전시 안내·Q&A 항목이 앞으로 올라오고 “나무 띠” 직접 근거가 1위에서 3위로 밀렸다. 그래서 위 방식으로 바꿨다.

# 측정

## 합성 세트

`tests/fixtures/evidence-selection.ts`는 가상의 등대 작품 근거 22개(작품 14, 전시 4, 작가 4)와 질문 16개다. 질문은 본문과 조사·어미가 다르게 썼다. 변경과 같은 작업에서 작성한 세트이므로 일반 정확도로 해석하지 않는다.

| 방식 | 12개 안에 직접 근거 포함 | 1위 |
| --- | ---: | ---: |
| 기존 | 14/16 | 8/16 |
| 변경 | 16/16 | 11/16 |

기존 방식이 놓친 두 건은 모두 조사가 붙은 작가·전시 공통 자료였다(판화도↔판화를, 연작은↔연작). 변경 후 가장 낮은 순위는 4위(“이 작품만 겨울 풍경인가요?”)다.

## 반 고흐 게시 버전 4 기록

Codex가 남긴 로컬 기록 `vangogh-v4-reconstructed-contexts.json`에는 작품당 전체 16개 중 **이미 선택된 12개**만 있다. 따라서 선택 여부가 아니라 12개 안의 순서만 비교했다. 직접 근거는 표의 핵심 표현이 들어 있는 발췌로 판정했다.

| 질문 | 직접 근거 표현 | 기존 순위 | 변경 순위 |
| --- | --- | ---: | ---: |
| 별밤 마을 | 보이지 않는 마을 | 3 | 4 |
| 별밤 목판화 | 목판화 | 1 | 1 |
| 해바라기 런던 작품 | 런던 | 8 | 1 |
| 해바라기 나무 띠 | 나무 띠 | 1 | 1 |
| 침실 원래 색 | 보랏빛 | 1 | 1 |
| 침실 물감 두께 | 두껍 | 1 | 1 |

별밤 마을은 질문의 “창밖·요양원”이 다른 발췌에도 있어 한 단계 내려갔다. 근거 없음 질문 세 건은 직접 근거가 없어 비교하지 않았다.

# 한계

- 모델 호출과 HTTP·DB 재실행은 하지 않았다. 순서 변화가 답변·보류 품질에 주는 영향은 측정하지 않았다.
- 전체 16개 후보를 재현하려면 해당 로컬 DB가 필요해 이번에는 실행하지 않았다.
- “검정↔검은색”, “상징↔비유” 같은 동의어나 “보였↔보이지” 같은 활용형은 여전히 맞추지 못한다. 임베딩·형태소 분석은 실제 작가 자료로 누락이 확인될 때 평가한다([제품 RAG 설계](../specs/rag-design.md)).
- 실제 관람객 질문이나 작가 자료로 측정한 결과가 아니다.
