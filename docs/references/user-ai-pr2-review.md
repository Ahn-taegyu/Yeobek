# 전달된 검토 요약

이 문서는 검토 전달 내용을 요약한 기록이며 사용자 발언의 축어 인용이 아니다. 검토 대상은 `e3c05f0`이다. 전달된 결과에 따르면 lint·typecheck·build·단위 162개·mock 비교·CI가 통과했고 실제 제공사 호출은 0회였다.

재현된 문제는 네 가지다. 601자 승인 해설이 2,000자 DB 상한과 달리 Q&A까지 막는다. 숫자만 입력한 `18`을 작품 번호·기본 해설 요청으로 처리하지 않아 이전 선택을 사용하거나 선택이 없으면 되묻는다. `이 작품에 대해 알려줘`, `작품 소개해 주세요`, `설명 부탁해요`, `해설 들려줘`, `18번`이 승인 해설을 재사용하지 않고 생성한다. `천 번을 봐도 좋네요. 재료가 뭔가요?`와 `이 번에 본 작품 재료는?`을 각각 1000번과 2번으로 잘못 해석한다.


검토에서는 의도를 명시적으로 전달하는 방안을 권고했다. 승인 해설 길이, 번호 판별과 해설 재사용 외에도 실제 제공사 호출이 없다는 검증 한계와 후속 통합 경계를 구분했다.

검토자는 공개 범위·소유권의 서버 저장소 경계, 근거 인용과 고정 문구 검증, 호출 횟수·시간·응답 크기 제한, 원문을 복사하는 자료 정리와 미검증 범위의 명시를 긍정적으로 평가했다. 다음 사항을 후속 검토 대상으로 전달했다.

- `publications.evidence`의 JSON 배열 검사와 하네스의 ID·버전·범위·출처·본문·해시 계약 사이에 차이가 있고 해설 인용을 저장할 자리가 없어 게시 migration 요구사항에 반영할 필요가 있다.
- 제공사 요청 형식은 모의 응답으로만 검사했다. 키 준비 후 `ai:smoke`와 제공 API 최소 1개 실제 사용을 확인해야 한다.
- 모델 평가 하한 4/4/4/3은 구현 설정이며 사람 라벨 비교 전 두 후보 방식의 품질 우위를 주장할 수 없다.
- `assertPluginTool`은 상수 사이의 일관성 검사여서 보안·권한 경계로 해석하면 안 된다.
- 자료 정리 후보를 적용하면 선택 section의 본문·출처가 교체되고 이력이 없으므로 검수 화면 전에 이력 보존 방법이 필요하다.
- 생성 답변의 URL 차단은 공개 작가 누리집도 거부할 수 있다. 공백 기준 검색은 한국어 조사에 취약하고, 한 section의 원문 합계가 5,000자를 넘으면 후보 전체가 실패한다.

사용자 검토에서는 실제 제공사 호출, 음성 품질, 사람 평가, `candidate-selection.md` 연구 문서의 세부 내용을 확인하지 않았다. 위 내용은 사용자 리뷰 요약이며 구체적인 수정 설계·검증 결과는 [수정 검토서](../reviews/ai-harness-fix-review.md)에서 구분한다.
