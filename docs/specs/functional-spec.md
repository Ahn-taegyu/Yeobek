# 1. 문서 사용법과 확정 수준

작가가 자료를 등록하고 해설·예상 Q&A를 검수해 게시하면, 관람객은 로그인 없이 단일 채팅에서 글·음성으로 질문하고 글 답변과 TTS를 이용한다.

기존 v0.3을 상세화한 **설계 검토본 v1.0**이다. 버전 번호는 제품 출시·구현 완료·사용자 승인 표시가 아니다. 다음 세 문서를 하나의 기능 명세로 사용한다.

| 문서 | 담당 내용 | 후속 산출물에서 참조할 ID |
| --- | --- | --- |
| 이 문서 | 범위, 권한, 입력, 상태, 업무 규칙, API 작업 | F-xxx, BR-xx, OP-xx |
| [화면 상세](screen-spec.md) | 화면 구성, 진입·이탈, 버튼, 표시 상태, 반응형 | SC-Axx, SC-Vxx |
| [시나리오·예외·수용 기준](user-scenarios.md) | 정상·대체 흐름, 실패 복구, 완료 판정 | UC-xx, EX-xx, AC-xx |

# 2. 범위와 완료 경로

**작가:** F13 로그인/가입 선택 → 가입자는 직접 로그인 → 작가 온보딩·홈 → 전시 기본 정보·선택 작품 세계 → 작품과 자료 → 해설·예상 Q&A 생성 → 작가 검수·승인 → 전시 공개와 공개 주소 배포.

**관람객:** 공개 전시 주소 → 공개 확인 → 전시 소개 → 단일 채팅 → 글·음성 질문, 작품 탐색·선택, 글 답변과 음소거 가능한 TTS.

후속 기능은 비활성 메뉴로 먼저 노출하지 않는다. [전체 23개 기능과 원안 우선순위](../product/mvp-priorities.md)는 보존한다. 제공 API 최소 1개 실제 사용은 완료 조건이며 모의 응답으로 대체해 완료 처리하지 않는다.

## F14 작가 홈

유효 세션으로 자기 홈에 진입한다. 기본 작품 세계 등록 전/완료 상태와 편집 진입을 제공하며 미등록 상태에서도 전시 생성이 가능하다. 내 전시만 조회하고 전시명·기간·장소·공개 상태와 관리 진입을 표시한다. 로딩·오류·빈 목록을 구분하고 재시도와 첫 전시 생성 경로를 제공한다. 저장 후 돌아오면 새 상태를 반영한다. 카드/리스트·정렬·검색·삭제·복제의 세부는 미확정이다. 홈 상태 명칭과 기준은 아래 v3 결정을 따른다.

로그인 후 작가 온보딩에서는 이름·작가명·이메일이 필수다. 나머지는 건너뛸 수 있고 성별은 기본 수집하지 않는다. 인증 이메일을 다시 입력받을지는 구현 전에 정리한다. 홈의 준비중은 미공개 또는 시작 전, 진행중은 공개·기간 내, 종료는 종료 시각 경과다. 미공개이면서 종료된 전시의 탭은 준비중이 우선이다(SRC-048). [v3 범위 결정](../references/user-v3-decisions.md).

### 작가 공통 작품 세계 입력

[사용자가 전달한 질문지](../references/user-artist-questionnaire.md)의 7개 답변을 별도 항목으로 저장한다. 작업 계기, 핵심 관심사, 예술관 및 철학, 사용하는 표현 방식, 그 표현 방식을 선택한 이유, 영감의 원천, 관람객과의 소통이다. 두 표현 방식 질문은 서로 다른 ID를 쓴다. 기존 소개·작품 세계 자유 입력 자료를 삭제하거나 새 항목으로 자동 추정하지 않는다. 미등록이어도 전시를 만들 수 있고 새로운 필수 조건은 추가하지 않는다.

## F01 전시 생성

| 동작 | 필수 검증 | 선택 내용 |
| --- | --- | --- |
| 두 단계 각각 임시저장 | 필수값 누락 허용. 입력된 값의 형식 오류와 저장 실패는 안내 | 일부만 저장 가능. 저장 후 같은 단계에 머무름 |
| 1단계 다음 | 전시명, 시작 날짜·시간, 종료 날짜·시간, 장소와 기간 순서 | 기획 계기·배경, 공간·작품 배치 의도, 관람객 특별 안내 |
| 2단계 완료 → 작품 등록 | 1단계 필수값과 기간을 재검증 | 집중·탐구 주제, 기존 작품 세계와의 관계, 전달 메시지, 이전 작업과의 차별점, 감상 시 주목할 부분, 기대하는 관람 경험. 모두 비어도 완료 가능 |

날짜와 시간은 선택 UI에서 입력한다. 뒤로 이동 시 입력값을 유지하고 다음 버튼은 저장과 단계 진행을 연결한다. 임시저장 API를 유지하며 초안은 자기 홈에서 다시 열어 이어 쓴다. 작업 ID 또는 기존 저장 버전으로 중복 생성과 덮어쓰기를 방지한다. 작성 진행 상태와 공개 상태는 별도다. 미완성 전시는 공개하지 않는다.

## F02 작품 및 자료 등록

한 화면에서 작품 추가·펼치기/접기·삭제·재정렬과 일부 저장을 제공한다. 번호는 전시 내에서 고유하며 초안 순서에 맞춰 갱신한다. 공개 번호 적용 시점과 라벨 교체는 F07 정책과 함께 검토하며, 기존 공개본은 새 초안 순서로 즉시 바뀌지 않는다.

| 구분 | 항목 | 적용 |
| --- | --- | --- |
| 기본 정보 | 작품명, 제작년도, 작품 크기 및 단위 | 작품명은 최종 등록 필수 제안. 제작년도·크기는 선택. 임시 제목/부분 저장 허용 |
| 제작 계기·영감 | 이 작품을 제작하게 된 계기나 영감은 무엇인가요? | 선택 |
| 표현·탐구 의도 | 이 작품을 통해 표현하거나 탐구하고자 한 것은 무엇인가요? | 선택 |
| 조형 요소의 의미 | 색채, 형태, 소재, 구도 등에서 특별한 의미를 담은 요소가 있나요? | 선택 |
| 제작 과정·어려움 | 작품을 제작하면서 특별히 기억에 남는 과정이나 어려움이 있었나요? | 선택 |
| 감상 시 주목할 부분 | 관람객이 이 작품을 감상할 때 주목했으면 하는 부분은 무엇인가요? | 선택 |
| 전시 주제와의 관계 | 이 작품은 이번 전시의 전체 주제와 어떻게 연결되나요? | 선택 |
| 첨부 | 작품 사진, 도록 및 참고 자료 | 선택. 미첨부 저장 가능. 업로드 진행·실패·삭제 처리 |

기존 자료의 재료 등 메타데이터와 비공개 저장·발췌 계약을 보존한다. 'AI 학습시키기'는 저장된 전시·작품 자료로 F04 생성 작업을 시작하는 화면 문구다. 최소 등록 항목과 파일 세부 정책은 구현 전 검토한다.

## F04 생성과 F05 검수

F04는 등록된 작가·전시·작품 자료와 참고 자료를 근거로 작품별 기본 해설 및 예상 질문·답변, 전시 전체 예상 질문·답변의 초안을 생성한다. 초안에 대상과 출처를 기록하고 진행·성공·실패·재시도를 표시한다. F03 인터뷰 없이 진행한다. 기존 후보 비교 절차의 적용 범위와 예상 질문 수는 미확정이다.

F05는 기본 해설 원고 검수와 작가용 AI 미리보기를 별도 화면으로 제공한다. 기본으로 생성된 작품 소개는 직접 수정할 수 있다. 나머지 답변은 지시문으로 새 초안을 만들고 다시 검수한다. 작가용 AI 미리보기에서 작품을 선택해 질문하고 응답별 정확성 평가와 정정을 저장한다. 수정 후보에도 출처·승인·공개 조건을 적용한다. 미리보기 평가 횟수와 검수 완료 조건은 미확정이다. [v3 검수 결정](../references/user-v3-review-decisions.md).

**구현 제안:** 사실을 정정하는 지시문은 문체·길이 조정과 구분한다. 사실 정정은 작가가 제시한 출처와 대상·버전을 함께 기록하고, 검수와 승인 후 근거에 반영한다. 지시문 자체로 승인 근거가 생기지 않는다.

## F07 공개와 F08 답변 사용

F07에서 전시 기본 정보·작품·AI 검수 등 공개 조건의 충족 여부와 보완 화면 링크를 표시한다. 기본 작품 세계와 작품 이미지는 선택이다. 확인과 서버 재검증 후 게시하며 공개 링크 복사와 기존 번호 라벨 계약을 유지한다. QR 제작은 MVP에서 보류한다. 비공개 전환 후 공개 페이지·문맥·미디어 접근을 차단한다. 시험용 해설은 개발 시연에서만 허용하며 운영 게시를 차단한다. 필수 승인 범위와 게시 음성 정책은 구현 계약과 대조해 확정한다.

F05에서 승인하는 단위는 해설 또는 질문·답변의 특정 버전이다. F07 게시 시 활성 공개본에 승인 버전과 허용 출처를 연결한다. F08은 해당 전시의 활성 공개본만 조회해 일치하는 승인 해설과 승인 Q&A 또는 정정 답변을 사용할 수 있다. 이를 새 자유 질문의 답변 생성·검증 근거로도 사용하며 질문 범위를 사전 생성 목록으로 제한하지 않는다. 작가 편집 중인 내용, 미승인 생성 결과와 미리보기 기록은 공개 후보에서 제외한다. 수정·재승인만으로 활성 공개본을 교체하지 않으며 교체 게시·철회 후에는 이전 답변 캐시와 음성 참조도 재검증한다.

서버는 모든 관리자 요청에서 인증과 소유권을 검사한다. 클라이언트의 `owner_id`, `approved`, 출처 목록을 권한의 근거로 신뢰하지 않는다. 타인 리소스는 존재 여부를 드러내지 않는 접근 불가 응답을 사용한다. 운영 기록에 원음·질문 전문을 분석 목적으로 추가하지 않는다.

# 4. 입력과 데이터 계약

**내부 지식 문서**는 작가·전시·작품별로 분리한 AI 참고용 입력 원본이며 사용자용 위키 화면을 뜻하지 않는다. 저장·관계·출처·재사용은 [SPEC-010](artist-knowledge.md)을 따른다. **원자료**는 비공개 PDF·메모, **공개 근거**는 작가가 공개 승인한 발췌/직접 작성 내용, **해설**은 승인된 기본 설명이다. **공개 묶음(Publication)**은 작품 표시 정보·이미지·근거·해설·음성이 일치하는 불변 버전이다. **현재 작품**은 지금 지칭하는 대상이며 처리 중 요청의 대상과 구별한다. **확인된 부위**는 말·글로 확인한 위치/모양으로, 이미지 인식 결과가 아니다.

## 4.1 입력 필드와 검증

이번 MVP의 작가 자료 입력 길이 단위는 유니코드 코드포인트이며, 후속 자료 편집기 카운터도 같은 기준을 사용한다. 로그인 폼의 HTML maxLength는 브라우저의 UTF-16 단위 제한이므로 이 자료 본문 계약과 구분한다. section 본문 API·DB는 JavaScript `trim()`에 해당하는 앞뒤 공백을 제거하고 5,000자 상한을 검사한다. 기존 본문과 정규화 결과가 같으면 기존 원문을 보존한다. 코드포인트는 화면의 결합 문자·복합 이모지 묶음 수와 다를 수 있으며, 원래 표시 문자 제안을 이 기준으로 구체화했다. 기존 기술 상한 이외의 길이·번호 범위는 이번 설계의 초기 제안이다. HTML은 실행하지 않고 일반 텍스트로 취급한다.

# 5. 업무 규칙

## BR-01 저장·미저장·동시 편집

명시적 `저장`을 기본으로 하고 성공 시 서버 revision과 저장 시각을 갱신한다. 오류 시 입력을 유지한다. 미저장 내부 이동에는 `계속 편집 / 저장 후 이동 / 변경 버리기`를 제공한다. 새로고침·탭 종료의 미저장 복구는 보장하지 않으며 브라우저 이탈 경고는 보조다.

저장·승인·음성·게시 요청은 기준 revision을 검사한다. 다른 탭의 수정과 충돌하면 자동 덮어쓰기 대신 로컬 입력을 유지하고 최신본 조회·수동 재적용을 안내한다.

## BR-02 자료와 공개 승인 분리

업로드는 `허가 → 전송 → 서버 완료 검증 → 자료 연결` 순서다. 파일 전송 성공만으로 완료가 아니다. 실패 시 텍스트와 다른 완료 파일을 유지하고, 교체 파일 완료 전 기존 파일을 제거하지 않는다. 원본 PDF·메모는 비공개이며 발췌 공개가 원본 전체 공개를 뜻하지 않는다. 전시 공통·작가 공통 근거도 사용할 전시에서 승인하고 각 공개 묶음에 원본 문서/section/revision과 근거 버전을 고정한다. 연결된 작가 위키 전체를 공개하지 않는다.

## BR-03 생성·재생성·검수

저장 작품 정보와 선택한 근거 초안으로 생성한다. 사진만으로 작가 의도·대상을 추론하지 않는다. 결과에 사용 근거·검토 상태를 표시하며 근거 부족/잘못된 인용은 승인 가능한 완성본으로 표시하지 않는다.

재생성은 새 후보를 보여주고 `후보 적용 / 기존 글 유지`를 선택하게 한다. 생성 중 자료가 바뀌면 이전 revision 결과임을 표시하고 자동 적용·승인을 막는다. 작가가 직접 추가한 문장도 근거를 연결하거나 직접 작성 근거로 등록한 후 승인한다.

## BR-04 승인과 음성 준비

근거별 공개 승인과 해설 승인을 분리한다. 해설이 쓰는 근거가 모두 공개 승인되어야 해설 승인 가능하다. 선택 해제된 근거를 인용하면 수정 위치와 차단 사유를 표시한다. 미저장 수정은 먼저 저장한다.

근거/해설 변경은 해당 초안 승인과 파생 음성을 무효화한다. 승인 해설만 음성으로 만든다. 같은 글 해시·음성 설정의 검증 파일은 재사용할 수 있으나 새 승인 버전과의 연결을 검사한다. 기본 해설 음성 준비가 관람객 Q&A 전체의 음성 사전 생성 요구는 아니다.

## BR-05 선택 게시와 조건

전시 안의 **선택한 작품 묶음**을 게시한다. 최초 공개는 준비 작품≥1개가 필요하다. 미완성 작품은 초안으로 남긴다. 게시 대상으로 고른 작품 중 하나라도 미준비면 전체 요청을 차단하고 작품별 사유를 반환한다.

F07 공개 체크리스트는 전시명·기간·장소, 최소 작품 1개, 전시 내 번호 고유성, 공개 필수 콘텐츠 승인 여부를 검사한다. 기본 작품 세계·참고 파일·작품 이미지는 선택이다. 전시 파일은 전시 공통 참고 자료로 연결한다. 기존 구현과 v3 조건의 차이는 [API 계약](api-contract.md)을 따른다. 서버는 승인 버전과 출처를 다시 검사한 뒤 공개 참조를 한 번에 교체하고, 실패하면 활성 상태를 유지한다.

전시 기본 정보만 게시하거나 기존 전시를 재게시할 때 선택하지 않은 기존 공개 작품은 유지한다. 목록에서 빼려면 `작품 공개 중지`를 사용한다. 작가·전시 소개를 바꾸는 과정에서 기존 해설/Q&A의 근거도 변경하면 단순 표시 정보 게시만으로 근거 버전을 교체하지 않고 해당 작품의 검수·게시 경로를 따른다.

## BR-06 일반 수정과 번호 변경

일반 수정은 새 초안이다. 새 승인·음성·게시 전까지 기존 공개본을 유지하고 `공개 vN / 수정 중`을 함께 표시한다. 생성·음성 실패가 기존 관람을 중단시키지 않는다.

번호는 새 게시 시 변경하고 라벨 재출력을 안내한다. 불변 작품 ID와 공개 전시 주소를 유지한다. 초안 번호와 현재 공개 번호의 충돌을 예약·최종 게시 검사로 막고 다른 작품에 조용히 재배정하지 않는다. `18→19` 변경 후 18번을 19번의 별칭으로 자동 연결하지 않는다.

## BR-07 중지·철회·삭제

전시 중지는 모든 공개 경로, 작품 중지는 해당 작품만 막는다. 마지막 공개 작품 중지 시 전시도 `paused`가 된다. 재개는 삭제/철회되지 않은 준비 묶음의 조건을 다시 검사한다.

**일반 초안 수정과 공개 자료 철회는 다르다.** 권리·개인정보·내용 오류로 근거를 철회하면 그 버전을 참조하는 모든 활성 작품을 즉시 중지한다. 확인 창에 공통 근거의 영향 전시·작품 수를 표시한다. 공유 작가 근거는 같은 소유자의 다른 전시와 전시 공개 소개의 참조까지 검사한다. 전시 소개가 철회 내용을 사용하면 전시 공개 게이트를 닫는다. 철회 내용에 기존 공개본 유지 규칙을 적용하지 않는다.

작품/자료 삭제는 참조를 검사하고 활성 공개의 중지·철회를 완료한 뒤 논리 삭제한다. 초안 삭제도 파생 글·음성 연결을 정리한다. 삭제 ID·URL은 재사용하지 않는다. 파일·파생물·검색·캐시 정리를 재시도 가능하게 기록하며 물리 정리 실패에도 공개는 계속 차단한다. 전시 전체 영구 삭제 UI·물리 보존 기한은 이번 화면 범위 밖이며 Q-04에서 관리한다.

## BR-08 공개 접근과 오래된 콘텐츠

전시 상태·작품 상태·활성 publication·철회를 목록/직접 URL/답변/출처/이미지/음성 모두에 적용한다. 원본 PDF와 raw Storage URL은 관람객에게 반환하지 않는다. 미디어는 서버 검사 후 `no-store`로 제공한다.

답변 전달 직전과 음성 생성/재생 직전에 재검사한다. 생성 중 버전 교체는 `CONTENT_CHANGED`로 안내하고 새 버전으로 다시 요청한다. 복원한 기록은 공개 확인 전 본문·출처·미디어를 표시하지 않는다. 비활성/철회 버전이면 해당 메시지 위치에 이용 불가 안내만 남긴다.

이미 전달된 콘텐츠/다운로드 파일 회수는 보장하지 않는다. 첫 MVP는 중지 푸시가 없으므로 열린 화면은 다음 요청·재생·복귀 검증 때 반영한다. 중지 응답을 받으면 관련 표시·재생을 즉시 중단한다.

## BR-09 진입·선택·번호 해석

공개 전시 주소는 공개 확인 후 SC-V05 전시 소개를 연다. 여백 채우러 가기를 누르면 SC-V01 채팅을 연다. 작품은 채팅 목록에서 선택하며 선택만으로 질문·답변을 만들지 않는다. 번호 단독 입력을 어떤 동작으로 해석할지는 검토한다.

번호는 전시 안에서만 해석한다. 이번 요청의 명시적 번호/선택이 현재 작품보다 우선한다. `01/1`, `18번/십팔 번`을 정규화하고 모호한 복수 후보는 되묻는다. 질문 속 연도·수량을 자동으로 작품 번호로 바꾸지 않는다. 미존재/비공개 번호는 같은 안내로 처리하고 현재 작품을 유지한다.

공개 목록은 한 줄과 전체보기로 제공한다. 선택 작품명으로 목록을 열고 현재 작품을 다시 고르면 전시 전체 질문으로 돌아간다. 조회와 선택은 채팅 기록을 유지한다. 명시적인 다른 공개 작품 요청은 해당 작품 근거를 조회한다.

## BR-10 해설·질문·부위

기본 해설은 승인본을 그대로 반환한다. 요약·꼬리 질문은 현재 공개 작품과 해당 전시에 승인된 전시 공통·작가 공통 근거로 생성한다. 내부 위키의 연결만으로 다른 전시 자료를 따라가지 않는다. 출처 라벨·발췌·쪽수만 공개하고 인용을 검증한다. 실시간 답변에 작가 사전 승인 배지를 붙이지 않는다.

근거 문맥은 기존 기술 기준의 총 8,000자·최대 12개 발췌 안에서 선택하고 출처/작품 경계를 자르지 않는다. 최근 대화는 같은 작품의 의미 해석용으로만 제한 전달한다. 초기 제안은 최근 6개 메시지·총 3,000자 이내이며 오래된 문맥부터 제외한다. 이 예산 때문에 근거가 불충분하면 추측 대신 확인/보류로 처리한다.

현재 작품이 없으면 선택을 요청한다. 모호한 “이 부분”은 위치/모양을 묻고, 승인 자료에 대상 설명이 없으면 확인 불가로 답한다. 등록 이미지를 분석한 것처럼 표현하지 않는다. 이전 채팅·모델 답변·사용자 주장은 승인 근거가 아니며 자료 속 지시문은 실행하지 않는다.

## BR-11 글·음성 질문과 TTS 음소거

질문은 글·음성을 지원하고 답변은 글과 음소거 가능한 TTS를 제공한다. 마이크는 녹음 버튼을 눌렀을 때 요청한다.

녹음 버튼으로 시작·종료하고 음성을 인식한다. 인식 후 자동 전송 또는 인식문 확인은 미정이다. 기존 구현과 검사에서는 확인 후 전송을 사용한다. 비어 있는 인식문은 전송하지 않으며 원음은 기존 임시 처리 경계를 따른다.

입력 오류 후 텍스트로 바꿔도 출력 선호를 유지한다. 출력 변경은 새 질문/LLM 답변을 만들지 않는다. 음성→텍스트는 재생을 멈추고, 텍스트→음성은 이후 답을 낭독하되 기존 답은 `듣기`로 요청한다. 자동재생 제한 시 재생 버튼을 제공한다.

## BR-12 처리 중 전환

한 채팅에서 답변 생성 1개만 진행하고 추가 전송은 잠근다. 작품 탐색·모드 변경은 가능하다. 요청에 전송 당시 작품·publication·문맥 순번을 고정한다. 늦은 답은 원래 질문 아래와 원래 작품 라벨에 붙이며 최신 현재 작품을 되돌리지 않는다.

작품 전환은 재생과 이전 요청 자동 낭독을 중단한다. 응답 도착 시 **현재 출력 모드**로 표시·낭독을 판단하되 요청 이후 작품 문맥이 바뀌면 자동 낭독하지 않는다. 텍스트로 바꾼 뒤 도착한 TTS도 재생하지 않는다. 과거 답 수동 듣기는 기본 출력 모드를 바꾸지 않는 1회 동작이다.

## BR-13 대화 유지·만료

탭 sessionStorage에 전시별 대화·모드를 보관한다. 같은 탭 새로고침은 공개 버전 검증 후 복원하며 새 탭/기기 간 이어보기는 보장하지 않는다. 저장소 사용 불가 시 메모리로 이용하고 새로고침 때 기록이 사라질 수 있음을 알린다.

서버 답변/음성 재시도 상태는 1시간 유효하다. 브라우저 기록이 TTL을 연장하지 않는다. 만료 Q&A 음성은 `다시 질문하기`로 안내하며 클라이언트의 임의 답변을 낭독하지 않는다. 기본 해설은 현재 공개본을 재요청할 수 있다. 1시간은 접근 유효기간이며 물리 삭제 완료 보장은 아니다.

서버 답변이 만료되어도 현재 공개 버전 검증을 통과한 로컬 기록의 글은 읽을 수 있다. 이 글을 서버가 검증한 답변으로 재등록하거나 임의 합성하는 것은 허용하지 않는다. 공개 버전 교체/철회는 TTL과 별개로 본문·출처·미디어 표시를 차단한다.

## BR-14 실패·중복·한도

변경/생성에는 request ID와 대상 revision을 쓴다. 같은 ID·내용의 재전송은 진행 상태/기존 결과를 반환하며 같은 ID의 다른 내용은 거부한다. 확정 실패의 재시도는 새 attempt로 처리한다. 실행 여부 불명·응답 유실은 먼저 상태를 조회하고 새 생성을 바로 보내지 않는다. 외부 제공사 과금의 완전한 중복 방지까지 보장하지 않는다.

외부 호출 30초 타임아웃·해당 서버 경로 최대 60초, 생성/STT/TTS 합산 세션별 분당 6회의 기존 초기값을 따른다. 기존 해설·음성 재사용/상태 조회는 생성 횟수에 다시 더하지 않는다. 세션 ID 변경만으로 전시 전체 한도를 우회할 수 없게 서버가 통제한다. 일일 상한은 실호출 후 설정한다. 무한 자동 재시도는 없다.

외부 장애/한도에도 준비된 해설·음성은 제공한다. Q&A 오류를 기본 해설이나 가짜 답변으로 조용히 대체하지 않는다. 재시도 가능 여부·대기 시간·유지된 결과를 안내한다.

## BR-15 내부 지식과 작가 공통 정보

작가·전시·작품은 연결된 내부 문서로 저장하고 UI는 일반 폼으로 제공한다. DB가 원본이며 기획 docs·별도 Markdown 파일을 이중 원본으로 두지 않는다. 작가와 전시의 식별 정보, 문서 sections·출처·소유권을 함께 검증한다.

동일 작가의 여러 전시는 작가 원본을 참조한다. 일반 원본 수정은 해당 초안만 바꾸고, 공개 전시에는 버전이 고정된 정보·근거가 유지된다. 최신 정보 반영은 필요한 전시에서 선택·검수·게시한다. 철회는 BR-07에 따라 같은 근거를 쓰는 모든 전시·작품의 새 접근을 차단한다.

A02~A04는 자기 입력을 읽고 수정하는 화면이다. A05의 AI 참고 정보 패널은 작가 공통/전시 공통/작품 근거, 출처·사용 버전·승인을 표시하는 제안이다. 별도 위키 전체 탐색·그래프·Markdown 편집기는 MVP 조건이 아니다. 상세 필드와 RAG 경계는 [내부 지식 계약](artist-knowledge.md)을 따른다.

## BR-16 작가 가입·인증·계정 처리

[D-016](../decisions/D-016-artist-auth.md)과 [가입 인증 결정](../references/user-signup-security.md)에 따라 작가는 이메일·비밀번호·확인값으로 가입하고, 이메일 인증을 마친 뒤 직접 로그인한다. 가입 비밀번호는 8자 이상이다. 가입에 작가 소개·작품 세계를 요구하지 않는다. 관람객은 공개 전시 주소를 로그인 없이 이용한다.

| 항목 | 동작 및 설계 제안 |
| --- | --- |
| 진입 | 비로그인 작가는 SC-A08에서 로그인 또는 가입 선택. 유효한 세션은 서버 확인 후 자기 홈으로 이동 |
| 가입 | 이메일 형식, 비밀번호 8자 이상과 확인값 일치를 검증. 가입 요청이 접수되면 이메일 인증을 안내하고, 인증 완료 후 SC-A01에서 직접 로그인하도록 연결. 가입과 이메일 인증으로 관리자 세션을 열 수 없도록 인증 제공사와 연동 |
| 로그인 | 이메일·비밀번호를 검증하고 서버 인증 후 자기 홈 SC-A02로 이동. 신규 가입 계정은 이메일 인증이 끝나야 로그인할 수 있다. 기존 계정 로그인에는 신규 가입의 최소 길이나 추가 강도 규칙을 적용하지 않는다. |
| 접근 | 서버 인증과 소유권을 검사하여 다른 작가의 비공개 전시를 차단. 클라이언트의 소유자·권한 입력을 신뢰하지 않음 |
| 프로필 | 가입은 인증 계정만 만든다. 작가 프로필·내부 문서는 기존 구현처럼 첫 프로필 조회나 첫 전시 생성 때 계정당 하나로 만들며, 기본 작품 세계는 SC-A10에서 나중에 작성 |
| 오류 | 입력 오류, 인증 실패, 네트워크 실패, 중복 요청 및 응답 유실을 안내. 계정 존재 여부나 비밀번호를 불필요하게 노출하지 않음. 계정이 생성됐으나 연결에 실패한 경우 재가입 없이 확인·복구하는 방식은 설계 제안 |
| 세션 | 로그인 상태를 서버에서 확인. 로그아웃 성공 후 세션 종료·관리자 캐시 제거 및 SC-A08 이동. 만료와 종료 실패는 각각 안내 |

소셜 로그인, 비밀번호 추가 강도 규칙과 재설정, 인증 메일 재발송, 동의·보관, 세션 수명은 Q-09에서 관리한다. 가입 API, 제공사의 자동 세션 억제, 오류 복구와 버튼 활성화는 구현 제안이며 미검증이다. [개발 기반 현황](development-foundation.md).

# 6. 상태와 전이

상태 이름은 API 명세의 공통 어휘 제안이다. 서로 다른 객체를 단일 `status` 하나로 합치지 않는다.

| 대상 | 상태 | 전이·조건 |
| --- | --- | --- |
| 전시 | `draft / published / paused` | 준비 작품 게시→published; 전체/마지막 작품 중지→paused; 조건 재검사 후 재개 |
| 작품 초안 | `incomplete / editable / approved` | 정보 부족/편집 가능/검수 완료의 표시 상태; 공개 여부와 별개 |
| 근거 | `draft / approved / withdrawn` | 승인; 수정은 새 draft; 철회 버전 복구 불가, 새 승인 필요 |
| 해설 | `empty / draft / approved` | 생성/직접 입력→draft; 근거 검증·승인→approved; 수정→새 draft |
| 기본 음성 | `missing / processing / ready / failed / stale` | 승인본으로 생성; 글/설정 변경→stale; 실패 확정 후 재시도 |
| 공개 묶음 | `prepared / active / superseded / revoked` | 승인·음성 완료→prepared; 게시→active; 교체→superseded; 철회→revoked |
| 작업 | `processing / succeeded / failed / unknown / expired` | 불명 상태는 조회로 확인; 만료 후 결과 재사용 차단 |
| 채팅 결과 | `answered / clarify / insufficient / blocked / error` | 답변/확인 질문/근거 부족/공개·권한 제한/기술 오류 구별 |
| 녹음·인식 UI | `idle / recording / recorded / transcribing / transcript_review / failed` | 인식문 확인에서만 채팅 전송; 실패가 다른 모드를 변경하지 않음 |
| 답변 음성 UI | `not_requested / processing / ready / playing / paused / failed / expired` | 같은 메시지 글 해시, 한 번에 하나 재생 |

전시/작품 `paused`는 공개 게이트를 닫는다. 활성 묶음 참조가 남아도 공개할 수 없고 근거 철회의 `revoked`와 구별한다. 삭제는 `deleted_at` 등 별도 차단 표식으로 표현 가능하다. 실제 테이블/enum은 후속 설계에서 정한다.

## 8.1 공통 응답 요구

- 저장: 대상 ID, revision, 저장 시각, 상태, 다음 행동의 차단 사유. 클라이언트 성공 추정만으로 게시 버튼을 열지 않는다.
- 오류: 안정 업무 코드, 안내, 필드 오류, retryable, 필요한 retry_after, request ID. 키·내부 프롬프트·원본 경로·타인 ID는 제외한다.
- 채팅: `clarify/insufficient`는 정상 대화 결과이며 기술 실패와 구별한다. 인용은 승인 evidence ID·버전·라벨·쪽수·허용 발췌다.
- 대상 미정의 확인 질문은 artwork/publication이 없을 수 있다. 이 경우 전시 공개 상태를 검사하고 근거 인용을 꾸며내지 않는다. 정상 확인/근거 부족 안내도 선택한 출력 모드로 전달할 수 있다.
- 음성: 글 성공과 별도 상태다. TTS 실패가 글 재생성을 유발하지 않는다.
- 세션: 답변 재조회·낭독은 요청 세션에 묶는다. conversation ID만으로 다른 세션 답을 열지 않는다.
- 중복: request ID의 범위·유효기간·payload 충돌·실패 attempt를 정의하고 승인/게시/업로드 완료에도 적용한다.

# 9. 공통 UX·품질

모바일 관람을 우선하고 작가 화면도 휴대폰에서 동작한다. 좁은 화면의 2열 검수는 근거→해설 단일 열로 바꾸며 키보드가 입력/전송을 가리지 않게 한다. 버튼 글 라벨, 색상 외 상태 표시, 독립 모드의 선택 상태를 제공한다.

로딩·빈 상태·성공·차단·실패를 구별한다. 오류는 복구 버튼 옆에 표시하고 토스트만으로 끝내지 않는다. 패널을 닫으면 연 버튼으로 포커스를 돌린다. 이미지 대체 설명은 번호·제목을 쓰며 작가 의도를 자동 추정하지 않는다.

실기기 HTTPS에서 iPhone Safari/Android Chrome의 공개 주소 진입·마이크·녹음 형식·자동재생 제한·키보드·스크롤을 확인한다. 이미지 오류에도 글 탐색은 가능해야 한다. 과거 “3초 로딩/30초 생성”은 미검증 성능 보장으로 사용하지 않는다.

관람 화면에 “AI가 공개된 작가 자료를 바탕으로 답합니다”와 AI 음성 안내를 제공한다. 보관·마이크 안내는 제공하되 내부 모델·DB 설명을 관람 흐름에 넣지 않는다. 모의 데이터/API는 명확히 표시한다.

# v3 변경분 연결

v3 추가 범위는 로그인 후 작가 온보딩과 프로필·포스터(W10), 일괄 학습·지시문 재작성·평가(W11), 공개 포스터·이미지(W12)다. 이메일 인증 방식을 유지한다. QR 제작과 별도 도슨트 여운 화면 후보는 MVP에서 제외한다. 관람 서버 계약은 유지하고 세부 화면 구성은 프런트에서 결정한다. [요청 원문 SRC-044](../references/user-backend-plan-v3.md) · [범위 결정 SRC-045](../references/user-v3-decisions.md) · [후속 결정 SRC-046](../references/user-v3-review-decisions.md) · [진행 계획](backend-completion.md).

W10의 이름·작가명·인증된 계정 이메일 필수 조건은 작가 온보딩 완료에 적용한다. 기존 로그인·문서 저장 계약은 유지하며 활동 이력·키워드·사진·포스터는 선택이다. 완료는 승인/게시를 의미하지 않는다. [구현 계약](api-contract.md#w10-v3-온보딩사진홈-계약), [Figma 대조](../references/figma-authoring-v3.md)를 참고한다.
