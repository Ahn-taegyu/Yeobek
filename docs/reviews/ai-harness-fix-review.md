# 대상과 증거

[검토 전달 요약](../references/user-ai-pr2-review.md)의 기준 `e3c05f0`에서 lint·typecheck·build·단위 162개·mock 비교·CI 통과가 보고되었다. 실제 제공사 호출은 0회다. 이 수치는 수정 후 검증 결과가 아니다.

구조화 intent/번호, 승인 해설 재사용과 낭독 직전 현재 publication 대조는 [실행 계약](../specs/ai-harness.md)을 따른다. `contracts.ts`는 승인본 2,000자와 생성 답 600자를 구분한다. `harness.ts`는 명시적 의도를 우선하고 승인본 낭독 전에 공개 문맥의 본문·인용·publication ID/버전을 대조한다. `providers/http.ts`도 UTF-16 단위 대신 같은 코드 포인트 상한을 적용한다. 승인된 URL은 원문대로 전달하지만 생성 답변 URL 정책은 바꾸지 않았다. 설정 검사 함수 이름 변경은 구성 일관성 검사이며 인증·인가를 추가하지 않는다.

`context.ts`의 문장 판별은 제한된 보조 규칙이다. 명확한 횟수 표현은 제외하고 작품 번호로 보이지만 해석하지 못한 경우 확인을 요청한다. 모든 한국어 문장의 의미를 판별한다는 보장은 없으며 UI는 구조화 의도·선택 번호를 전달해야 한다.

# 직접 실행 및 교차 검토

- Sol의 번호·의도 구현과 Terra의 문서 변경을 실제 diff로 대조했다. 별도 Sol 리뷰에서 쉼표 번호 비교와 중간 문장 번호가 누락되는 회귀를 발견해 수정했고, 부모 에이전트가 문장 중간의 모호한 번호도 확인하도록 보완했다. 리뷰 원문과 구현자가 정한 필드·정책을 구분하도록 문서도 재수정했다.
- `tests/unit/ai-chat-intent.test.ts` 45건과 `tests/unit/ai-narration-boundaries.test.ts` 18건을 추가했다. 별도 회귀 파일이 `ai:eval`에서도 실행되도록 명령을 갱신했다. 승인본 변조·인용 불일치·게시 버전 차이·철회·비 BMP 문자·생성 답 상한 유지도 검사한다.
- 부모 에이전트가 `npm run lint`, `npm run typecheck`, `npm test` **225건**, `npm run build`를 직접 실행해 통과했다. 빌드는 기존 `.next` 생성 권한 제약 때문에 권한 있는 환경에서 실행했다.
- `npm run ai:compare -- --mode=mock`의 합성 5사례·두 방식 비교가 통과했다. 이 실행은 실제 모델 품질·비용·지연의 증거가 아니다.
- `python scripts/knowledge.py verify`는 문서 101개·기능 23개·Bases 3개 오류 0, 검색 회귀 9개 통과다. 원격 CI는 [PR #2 Checks](https://github.com/Ahn-taegyu/Yeobek/pull/2/checks)의 최신 커밋 결과를 확인한다. DB migration·실행 HTTP·의존성 변경은 없으며 새 DB 게시/이력 어댑터는 구현하지 않았다. 실제 제공사 호출은 여전히 **0회**다.

# 후속 및 검증 한계

- 실제 publisher는 승인 해설의 권위 있는 citation ID를 기록하고 각 근거의 ID·버전·소유자·전시·publication·작품 범위·label·본문·해시와 철회 상태를 검증해야 한다. 현재 SQL의 비어 있지 않은 JSON 배열 검사만으로는 충족하지 못한다. 자동으로 모든 근거를 인용하지 않는다. 신규 migration이 필요하다.
- 승인 전 한 번 정규화해 같은 값의 해시를 승인하거나 정규화하지 않은 원문이 2,000자를 넘으면 거부한다. 읽을 때 원문을 바꾸지 않는다.
- 현재 `api_requests`에는 답변 source/outcome/citations가 없다. 음성 HTTP 공개 전 신뢰 가능한 영속 저장이 필요하다.
- 작가 후보 적용은 이전 section·sourceRefs·revision 이력을 동일 CAS 트랜잭션에 append-only로 보존하고 만료·소유권·고정 출처·멱등성을 검사해야 한다. 무변경·재실행에 이력을 중복하지 않는다. 실제 DB 어댑터는 미구현이다.
- 생성 URL의 문자 패턴 차단은 공개 작가 URL도 거부할 수 있어 공개 링크 정책이 필요하다. 정확한 공백 토큰 검색은 한국어 조사에 취약하다. 합친 section이 5,000자를 넘으면 저장 전에 거부되며 재선택·분할 UX가 필요하다. 조용히 자르지 않는다.
- 제공사 포맷은 실호출로 미검증이다. smoke와 제공 API 1개 이상의 실제 사용이 필요하다. 모델 심사 4/4/4/3은 잠정이며 사람 라벨 보정 전 품질 주장 근거가 아니다.
