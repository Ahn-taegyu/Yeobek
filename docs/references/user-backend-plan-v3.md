# 전달 요구

사용자는 진행 중인 W10을 검토 가능한 커밋·PR로 보존한 뒤 v2에 아래 v3 변경분을 얹고 겹치는 부분은 v3를 우선하라고 요청했다. W13 → W10 → W9 → W11 → W12 → W8 잔여 → W6 → W2 → W7 순서다. 완료 묶음을 다시 만들지 않고 기존 계약을 유지하며 차이만 신규 migration과 필드로 추가한다.

A1은 **이메일+비밀번호 유지, 이번 범위에서 소셜 로그인 제외**로 확정했다. Figma 소셜 버튼은 디자인 수정 대상이며 이메일 가입·로그인·인증 안내 화면이 필요하다. 나머지 A2~A7·B1~B2·R1~R3는 한 번에 질문하고 답을 기다리는 동안 독립 작업을 수행한다. 답이 없으면 원문의 기본을 적용했다고 명시한다. 기본은 사용자 확정 결정과 구분한다.

화면 관련 묶음 시작 시 Figma 원문의 문구·선택지를 직접 확인하고 불가하면 2절 표만 사용한 사실을 기록한다. 화면 부재로 검수·승인·공개 기능을 빼지 않는다. 개인정보는 운영 집계·자동화 본문·운영 프롬프트에 넣지 않는다. 원격 보호 설정은 변경하지 않고 권한·migration PR에 사람 검토 지점을 남긴다. 플래그·상한 변경에 CI·검사·예제 설정을 맞추며 실제 검증만 완료로 기록한다.

전달 현황과 실제 차이: W10 v2 입력 계약은 PR #15에 보존됐고 직접 검사까지 수행했다. W2 PR #13의 TS2353은 d276d9f에서 수정되어 App/Knowledge CI가 성공했지만 여전히 미병합이다. 이 원문은 소급 고치지 않는다.

\### 새 화면 때문에 생기는 위험\
\
\- 이름·이메일·성별·활동 이력은 개인정보다. 운영 집계·자동화 본문·AI 프롬프트(운영 자동화)에 넣지 않는다. 제품 AI에는 작가가 입력한 작품 세계·활동 이력만 근거로 쓴다.\
\- 프로필 사진·포스터는 새 공개 미디어다. 기존 공개 미디어 검사(현재 공개본·해시·형식 고정)를 똑같이 거친다.\
\- 이메일 인증은 메일 발송이 필요하다. 운영 발송 설정과 발송 한도는 Supabase 공식 문서로 확인하고 키 당일 점검에 넣는다.\
\- 소셜 로그인은 채택하지 않았다. Supabase의 외부 제공사 로그인이 꺼져 있는지 설정에서 확인한다.\
\
\## 4. 묶음별 변경 (v2 대비)\
\
\### W13 — 보안·운영 보강 (신규, 먼저 한다)\
\
작고 서로 독립적이며 이후 묶음이 모두 영향을 받는다. 위 표의 1·5·6·8·9와 실행 시간 조정. PR 하나로 묶되 migration은 항목별로 나눈다. 플래그 기본값을 바꾸면 기존 테스트·CI·\`.env.example\`이 명시값을 쓰도록 함께 고친다.\
\
\### W10 — 입력 계약 (v2 + Figma)\
\
v2 범위에 더해:\
\- section 목록을 \*\*Figma 문구 기준\*\*으로 선언: 작가 작품 세계 7, 활동 이력 5, 전시 1단계 3, 전시 2단계 6, 작품 6. 기존 ID(\`bio\`·\`practice\`·\`introduction\`·\`theme\`·\`description\`·\`notes\`)는 유지.\
\- 프로필: 이름, 작가명(기존 \`displayName\`과의 관계 정리), 분야·분위기·주제 다중 선택(선택지 목록은 계약에 선언, "기타" 포함), 온보딩 완료 여부, 프로필 사진.\
\- 전시: 포스터 이미지, 시각(1시간 단위는 화면 제약이며 서버는 분 단위까지 허용), 기간 역전 사유 코드.\
\- 홈: 상태별 개수, 공개 상태와 기간 상태를 분리해 반환(A6).\
\- 작품: 순서가 곧 번호(재정렬 RPC가 번호 갱신), 제목+질문만으로 저장, 전시 범위 업로드.\
\- 업로드 종류 추가(\`poster\`, \`avatar\`, 전시 참고 자료)는 W13의 낮춘 상한을 따른다.\
\
\### W9 — 직접 가입 (v2 + 확정 정책)\
\
이메일 인증 필수·8자 이상·확인 후 직접 로그인은 확정이고, 소셜 로그인은 만들지 않는다(A1 결정). 이 결정을 \`docs/references/\`에 기록하고 D-016의 미결정 목록에서 소셜 로그인을 "이번 범위 제외"로 고친다. 인증 메일 재발송·만료 처리 경로를 포함한다(방식은 미결정이므로 최소 구현).\
\
\### W11 — 예상 Q&A·검수·미리보기 (v2 + Figma + 리스크 2)\
\
\- 전시 단위 일괄 학습 시작과 묶음 진행 상태(대상 이름 포함).\
\- 미리보기 답변 평가(정확/수정 필요)와 \*\*지시문 기반 재작성\*\* 플레이북: 지시문은 작가 입력이므로 근거가 아니다. 재작성 결과도 승인 근거 범위를 벗어나면 거부한다. 지시문·이전 답변·새 작업본을 연결 보관.\
\- 보완 요청: 재게시 시 자동 종료 대신 "재확인 필요". 작가 답변은 Q&A 작업본으로 들어간다.\

\### W12 — 공개·관람 (v2 + Figma + 리스크 12)\

\- 고정 문구·지침에 도슨트 이름 "여운".\

\- 모의 해설 게시 차단 규칙(R2의 답에 따름).\

보완 질문 요약은 본문 제한(건수·정제 주제)과 URL 차단을 먼저 넣은 뒤 켠다. 스티비 수신 거부 동기화 전에는 홍보성 안내를 보내지 않는다.\

\## 6. Verification\
\
