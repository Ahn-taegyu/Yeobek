# 변경과 재현

관람 질문의 구체적인 사실을 직접 확인하거나 반박할 문장을 우선한다. 용어가 달라도 뜻이 같으면 근거로 쓰고, 공개 승인된 편집·보존 발췌는 화자와 시점을 구별해 사용한다. 질문의 목적·원인·일화가 자료에 없으면 일반 배경으로 대신 답하지 않는다. 작가 의도는 계속 명시 진술이 필요하다.

별밤의 마을 질문은 실제 게시본에서도 한 번 더 보류되었다. 로컬 `load_publication_context`와 실제 `selectEvidence`를 재현하니 “창에서 보이지 않는 마을은 다른 경치에서 가져왔고”라는 직접 근거가 전달 발췌 12개 중 세 번째였다. “요양원 창에서 본 경치로 시작했다”는 포괄 진술은 마을까지 그대로 봤다는 말이 아니다. 이 실행에서 검색 누락과 직접 근거 부족은 관찰되지 않았다.

최종 하네스는 유효한 모델 보류 때, 같은 공개 발췌로 최대 한 번 더 질문의 핵심을 검토한다. 모델을 다시 부르기 전과 최종 반환 전에 공개 버전을 확인한다. 재검토의 응답이 근거 부족이거나 인용 계약을 어기면 최초 보류를 유지한다. 정상 보류에도 1회가 추가되므로 비용과 지연이 늘 수 있다. 정상 답변과 승인 해설에는 추가 호출하지 않는다. 허용 ID와 출력 형식만 서버가 확인하며 실제 의미적 근거 여부는 모델 판단과 직접 검토에 의존한다.

# 같은 입력의 수정 전후

기존 45개 결과에서 과잉 보류 5건, 실제로 근거가 없었던 보류 6건, 정상 답변 대조 2건을 선별했다. GPT-6 Luna에 질문·정렬된 발췌·ID·출력 계약을 고정하고 `66ddf2a`의 기존 프롬프트와 1차 수정 프롬프트를 각 1회 실행했다. 호출 순서는 번갈아 바꿨다. 이 비교는 **프롬프트만 변경한 중간 버전**이며, 최종 하네스의 추가 검토는 별도 게시본에서 확인했다.

- 침실 D: 기존 프롬프트 재실행은 보류, 수정 후 “벽과 문은 원래 보랏빛이었지만, 오랜 시간에 걸쳐 변색되어 오늘날에는 파랗게 보입니다.”

같은 이전 프롬프트에서도 한 건이 바뀌었다. 선별된 소표본을 각 한 번 실행했으므로 일반 개선율 및 일관성으로 해석하지 않는다. 수정본의 7개 근거 답변은 인용 본문과 대조했다.

# 독립 평가의 보류 처리

오프라인 `scripts/visitor-evaluation.mjs`는 평가 모델이 **각 후보가 받은 발췌만** 읽어 답변 가능 여부를 먼저 판정하도록 지시한다. 답변의 실제 인용과 문장의 뒷받침, 질문 핵심의 완결성은 별도로 본다. 코드에서 답변 가능 여부와 응답 상태를 대조하므로 근거가 없다는 판정에 올바른 `insufficient_evidence`가 오면 자동으로 상태가 일치한다. 허용되지 않은 후보·다른 후보의 발췌 ID·중복 ID·잘못된 배열은 결과로 채택하지 않는다. 이 평가를 관람 서비스나 작가 해설 평가에 호출하지 않는다.

Sonnet 5.5가 이전에 감점한 정상 보류 6건(별밤 추가 A/B, 해바라기 추가 A/B/C, 침실 추가 A)을 이전 답변 본문 그대로 다시 평가했으며 6/6이 적절했다. 정답표를 빼고 판정 순서·출력 스키마도 바꿨으므로 평가 지침 한 요소의 효과로 분리할 수 없다. 별밤 마을 평가 배치는 모델이 후보 UUID 한 개의 뒷부분을 바꾸어 전체를 폐기했다. 답변의 실제 인용·문장을 직접 대조했으며 임의로 ID를 교정하거나 재호출하지 않았다.

# 최종 로컬 반 고흐 데모

세 작품의 게시 버전 4가 계속 유효한 상태에서 같은 9문항을 `POST /api/chat`에 텍스트 입력·출력으로 보냈다. DB와 HTTP 및 승인 Q&A 문맥을 포함했다. 승인 자료·게시 상태를 다시 변경하거나 음성 인식·합성을 호출하지 않았다. 앱 요청 한도로 제공사 호출 전에 거부된 요청만 한도 적용 후 별도 실행했고, 모델에 전달된 결과는 성공 응답으로 덮어쓰지 않았다.

| 형태 | HTTP 완료 | 근거 있음: 답변 | 근거 없음: 보류 |
| --- | ---: | ---: | ---: |
| 1차 프롬프트만 적용 | 9/9 | 5/6 | 2/3 |
| 직접 반박과 관련 배경의 차이를 명시한 프롬프트 | 9/9 | 5/6 | 3/3 |
| 같은 범위를 한 번 더 검토하는 최종 하네스 | 9/9 | 6/6 | 2/3 |

최종 별밤 마을 답은 “아니요. 이 그림의 마을은 요양원 창밖에서 보이지 않아 다른 경치에서 가져왔습니다.”였다. 이 질문은 첫 호출에서 답했다. 나무 띠 질문은 첫 호출의 보류를 재검토가 바로잡아 “화면 위쪽을 넓히기 위해 나무 띠를 덧댔습니다.”라고 해당 근거를 인용했다. 침실의 원래 색과 현재 색이 다른 이유에는 보랏빛과 변색을 구별해서 답했다. 별밤·해바라기의 미확인 기록 두 질문은 재검토 후에도 인용 없이 보류했다.

남은 예외는 침실 꿈 질문이다. 모델이 공개 자료에서 그런 기록을 확인할 수 없다고 답하면서도, 별개의 제작 배경을 인용해 `answered`로 분류했다. 외계인이나 꿈이 있었다는 주장을 만들지는 않았으나 상태와 인용이 질문의 핵심에는 맞지 않았다. 이 응답은 모델이 보류하지 않아 추가 검토 대상으로 넘어가지 않았다. 9문항 전체 통과나 보류/응답의 완전한 일관성으로 해석할 수 없다.

이 측정 뒤 하네스는 첫 결과가 `answered`인 경우에도 같은 검토를 한 번 실행하도록 넓혔고, 검토 지침에 '기록이 없다는 문장에 관련 사실을 붙인 후보'를 보류로 분류하는 기준을 추가했다. 위 표는 확장 전 하네스의 결과다.

9문항 모두 기대 상태·출처·게시 버전 계약을 통과했다. 침실 꿈 질문은 이번에는 인용 없이 보류했다. 근거 있는 6문항은 모두 인용과 함께 답했고, 별밤 마을·나무 띠·침실 원래 색 답변은 앞선 측정과 같은 사실을 담았다. 모든 질문에서 검토 호출이 실행되어 Liner `openai/gpt-6-luna` 호출은 18회(질문당 2회), 제공사 `usage.cost` 합계 $0.005922655였다. 확장 전 최종 게시본의 12회, $0.002392235보다 호출은 1.5배, 비용은 약 2.5배다.

한 번 실행한 결과이며 반복 측정은 하지 않았다. 침실 꿈 질문이 첫 호출에서 이미 보류했는지, 검토가 답변을 보류로 낮췄는지는 호출 기록에 출력이 남지 않아 구분하지 못했다. 따라서 9문항 통과는 확장한 하네스의 이번 실행 결과이며, 상태 오분류가 해결되었다는 일반적인 증거는 아니다.

비용은 제공사 `usage.cost` 합계다. 1차 프롬프트 통제 비교는 생성 26회와 평가 5회, $0.310349085였다. 최종 게시본은 질문 9개에 실제 Liner 12회(추가 검토 3회), $0.002392235였다. 앞선 두 게시본 프롬프트 확인은 별도로 18회, $0.005528595였다. 키와 청구 정보를 조회하거나 출력하지 않았다.

실행 기록은 로컬 `.tmp/`에 있으며, 최초 `vangogh-input-quality-results.json`을 수정하지 않았다. `visitor-abstention.test.ts`는 통제 비교, `read-vangogh-text-context.test.ts`는 실제 선택 발췌 확인, `verify-vangogh-text-v4.mjs`는 실제 텍스트 API 검증에 썼다. 로컬 비교 원자료와 세션은 Git 공유 대상이 아니다.
