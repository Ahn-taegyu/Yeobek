# 전달 요청

사용자는 진행 중인 W8을 검토 가능한 커밋·PR로 보존하고 D0부터 v2 순서로 이어가도록 요청했다. 완료 묶음은 다시 만들지 않고 새 migration·필드로 차이만 메운다. 묶음 착수 때마다 기능·화면·시나리오·데이터 모델·RAG의 P0 원문을 읽고 요약과 다르면 원문을 우선하고 차이를 보고한다. 미결정은 질문하고 답을 기다리는 동안 독립 작업을 하며, 미응답은 기존 동작·플래그·정책값으로 남긴다. Git·검증은 최신 협업 규칙을 따르고 줄인 기능은 비활성·미구현으로 인계한다.

아래는 전달 파일의 원문이다. 전달 형식의 백슬래시를 포함해 보존한다. 당시 상태와 이후 실제 상태의 차이 및 새로운 가입 정책 답변은 작업 추적·별도 출처에 기록한다.

\## 3. 유지하는 원칙과 추가 규칙\
\
원 계획의 "변경에 강한 설계 원칙" 표, 파트너 API 우선(D-015), 응답 봉투 고정, 모의 제공사 모드, 새 migration만 추가하는 규칙을 그대로 쓴다. 추가:\
\
\- \*\*기존 계약은 깨지 않는다.\*\* 프런트가 아직 붙지 않았더라도 필드는 추가만 한다. 의미가 바뀌는 항목(작품 직접 진입, 출력 모드, 작품 미선택 처리)은 새 필드·플래그로 전환하고 계약 스냅샷 변경을 PR에 설명한다.\
\- \*\*section 목록을 한 곳에서 선언한다.\*\* 주체별 section ID·라벨·필수 여부·길이를 \`src/lib/contracts/\`의 목록 하나에서 파생시킨다(현재 "주체별 최대 2개" 고정을 대체). 안내 질문이 바뀌면 이 목록만 고친다.\
\- \*\*임시저장과 완료 검증을 분리한다.\*\* 저장은 형식만 검사하고, 필수값은 "다음/완료/게시" 전이에서 규칙 목록으로 검사한다(게시 규칙과 같은 방식, 차단 사유 코드 반환).\
\- \*\*새 P0 동작은 플래그 뒤에 둔다\*\*: \`signup\`, \`expectedQa\`, \`previewChat\`, \`exhibitionScopeChat\`, 기존 \`voiceRequired\`에 더해 \`imageRequired\`. 미결정이 풀리면 기본값만 바꾼다.\

\## 5. 남은 작업 묶음\
\
각 묶음은 원 계획과 같은 순서로 끝낸다: migration → RPC·pgTAP → 저장소 어댑터 → 플레이북 선언 → HTTP 경로 → 통합 테스트 → \`api-contract.md\`·\`development-foundation.md\`·\`backend-completion.md\`·\`log.md\` 갱신. 경로·표 이름은 제안이며 기존 이름과 충돌하면 기존 관례를 따른다.\
\
\### W9 — 작가 직접 가입 (D-016, SRC-038, BR-16, OP-23)\
\
\- 착수 전 Q-09를 묻는다. 최소한 "이메일 확인을 쓸지"와 "비밀번호 최소 길이"가 필요하다.\
\- 가입 경로 \`POST /api/auth/signup\`(제안): 이메일·비밀번호·확인값, 요청 ID. \*\*응답에서 세션 쿠키를 설정하지 않는다.\*\* Supabase가 가입 직후 세션을 돌려주는 설정이면 서버에서 버린다. 구현 방식(공개 가입 켜기 vs 서버에서만 계정 생성)은 Supabase 공식 문서를 확인하고 정한다. 어느 쪽이든 브라우저가 Auth에 직접 가입하지 못하게 한다.\
\- 세션 확인 \`GET /api/auth/session\`(제안): SC-A08이 로그인 여부를 서버에서 확인.\
\- 중복 이메일·제공사 거부는 계정 존재를 드러내지 않는 응답(EX-27 \`SIGNUP_UNAVAILABLE\`, 제안). 결과 불명·재시도가 계정을 두 번 만들지 않게 한다. 가입 시도에 호출 제한(\`app_policies\`).\
\- 프로필은 기존 지연 생성(첫 프로필 조회·첫 전시 생성)을 그대로 쓴다. 가입 계정으로도 계정당 1개가 지켜지는지 pgTAP으로 확인.\
\- 비밀번호를 로그·\`ai_jobs\`·\`api_requests\`·자동화 이벤트에 남기지 않는지 검사.\
\- 플래그 \`signup\`: 꺼지면 경로 404, 기존 사전 생성 계정 로그인은 영향 없음.\
\- 검증: UC/AC-20\~23 중 서버로 확인 가능한 항목(가입 직후 관리자 API 401, 직접 로그인 후 홈, 로그아웃 후 재접근 거부, 중복 가입 시 기존 계정 불변).\
\
\### W10 — 전시·작품 입력 계약 개정 (F14·F01·F02)\
\
\- section 목록 선언(위 원칙)과 migration: 문서 section 수 제한을 목록 기반 검증으로 교체. 작가(\`bio\`/\`practice\` + 기본 작품 세계 항목), 전시(1단계 선택 3항목 + 2단계 6항목), 작품(안내 질문 6항목). 기존 section ID는 유지한다.\
\- 전시: \`title\` 등 필수값을 임시저장에서 선택으로 완화(nullable), 시작·종료 \*\*시간\*\* 추가, 작성 단계(\`authoring_step\`) 열 추가. 전이 RPC \`advance_exhibition_step\`(제안)이 1단계 필수값·기간 순서를 검사하고 사유 코드를 반환. 2단계 완료는 선택 항목이 모두 비어도 통과.\
\- 작품: 부분 저장(임시 제목), 크기 단위, 초안 순서 열과 재정렬 RPC(전시 내 번호를 한 트랜잭션에서 갱신, 공개 번호 예약과의 충돌 검사는 기존 규칙 유지). 공개본 번호는 게시 전까지 그대로.\
\- 작가 홈: 전시 목록에 작성 단계, 프로필 응답에 기본 작품 세계 등록 여부.\
\- 기존 PATCH의 "전체 값 저장, 생략 시 null" 계약은 유지한다.\
\- 게시 규칙 쪽에서 "미완성 전시는 공개 불가"가 되도록 필수값 규칙을 W12와 맞춘다.\
\- 진행 안내(W8)의 상태 조회가 새 작성 단계를 읽도록 연결.\
\
\### W11 — 예상 Q&A 생성·검수·미리보기 (F04·F05)\
\
\- migration \`qa_items\`(제안): 범위(전시/작품), 질문, 답변 작업본, 근거 ID·버전, 기준 revision, 출처 구분(생성/미리보기 정정/보완 요청 답변), 상태(draft/approved/withdrawn), 버전·해시. 승인은 특정 버전을 고정한다. 상태 전이는 전이 표에 추가.\
\- 생성: 플레이북 \`expected-qa-draft\`(작품별·전시 전체). \`ai_jobs\` 종류 추가, 요청 ID 중복·일일 상한·재시도는 기존 원장 사용. 전시 단위로 한 번에 시작하는 경로("AI 학습시키기")는 작품별 작업을 예약만 하고 진행 상태를 묶어서 조회한다. 예상 질문 개수는 \`policy.ts\` 값(미결정).\
\- 기존 \`followUpQuestions\`(작가에게 되묻는 보완 질문)와 \*\*이름·저장을 분리\*\*한다. 서로 다른 개념이다.\
\- 검수: 목록·수정(새 작업본)·승인·철회 RPC와 경로. 기존 \`get_review_bundle\`에 Q&A 상태와 차단 사유 추가.\
\- 작가 전용 미리보기 \`POST /api/admin/exhibitions/{id}/preview/chat\`(제안): 인증·소유권 필수, 초안·승인 내용을 문맥으로 쓰되 \*\*공개 경로·공개 캐시·관람 한도와 분리\*\*. 응답별 평가·정정 저장 → 정정은 \`qa_items\`의 새 작업본이 되고 승인 전에는 공개 후보가 아니다. 미리보기 대화 기록 자체는 공개 근거가 아니다.\
\- 보완 요청 연결(제안): 작가가 \`qa_gaps\`의 질문에 답하면 같은 \`qa_items\` 경로로 들어가게 한다.\
\- 모의 제공사에 Q&A 초안 응답 추가, 계약 스냅샷 갱신.\
\
\### W12 — 공개 조건·전시 QR·관람 P0 (F07·F08)\
\
\- 게시 규칙 목록 개정: 전시명·기간·장소, 작품 1개 이상, 번호 고유, 승인 해설. 이미지·음성·승인 Q&A 필수 여부는 플래그(\`imageRequired\`, \`voiceRequired\`, 정책값)로 두고 \*\*기본값은 사용자 확인 전까지 현재 동작\*\*. 체크리스트 응답은 조건별 충족 여부와 보완할 화면 식별자를 준다.\
\- 공개 스냅샷에 승인 Q&A 포함(\`schemaVersion\` 증가, 이전 버전 읽기 유지). 교체 게시·철회 시 기존 캐시·음성 재검증 경로에 Q&A를 포함.\
\- 전시 QR 1개: 라벨 응답이 작품별 진입 주소를 내고 있으면 제거 대상이다(현재 응답 형태를 먼저 확인). 전시 주소 하나와 번호·제목만 준다. 공개 작품 조회 API는 채팅 목록·정보용으로 유지한다.\
\- 공개 전시 응답에 소개 화면용 필드(전시명·장소·기간과 시간).\
\- 채팅: 작품이 없을 때 선택을 요청하던 동작을, 플래그 \`exhibitionScopeChat\`이 켜지면 \*\*전시 전체 맥락\*\*(전시 공통·작가 공통 승인 근거 + 전시 범위 승인 Q&A)으로 답하도록 한다. \`load_publication_context\`가 승인 Q&A를 반환하고 \`visitor-answer\`가 이를 근거로 쓴다. 승인 답변의 직접 반환은 미결정이므로 기본은 "근거로만 사용".\
\- 출력: 글 답변은 항상 반환, 낭독은 클라이언트의 음소거 상태에 따라 요청. 기존 \`outputMode\` 계열 필드는 받아들이되 의미를 바꾸지 않고, 새 흐름은 별도 필드로 표현한다.\
\- 작품 선택 시 안내 음성(W5에서 구현)은 "선택만으로 음성 없음"과 충돌하므로 플래그로 끄고 기본값을 꺼짐으로 바꾼다.\
\- 인식 후 자동 전송·번호 단독 입력은 미결정 → 기존 동작 유지.\
\
\### W8 잔여 — 업무 자동화\
\
원 계획에서 남은 것: 승인 독촉·전시 종료의 예약 안내, Alt 전사 가져오기(수신 웹훅·\`author-intake-transcript\`), 보완 질문 요약, 실패 작업 분류, 운영 브리핑, 문의 본문의 물리 보존 삭제와 운영 로그 확인.\
\
새 기획 반영:\
\- 이벤트 추가: 가입 완료(환영·시작 안내, 거래성), 생성 완료 후 검수 대기 N일, 임시저장 후 미완성 N일. 수치는 \`app_policies\`.\
\- 안내 문안의 단계 이름을 P0 흐름(작가 홈→전시→작품→생성→검수→공개)에 맞춘다.\
\- 수신 동의는 가입 시 받지 않는다(D-016: 가입 폼 최소화). 동의 전에는 홍보성 발송 금지, 거래성 범위는 기존 정책을 따른다.\
\- Alt 전사 가져오기는 후보 저장(W2)에 의존한다. W2를 먼저 한다.\
\
\### W6 — 운영 집계 API\
\
원 계획 그대로 + 자동화별 처리·자동 비율·개입 건수 + \*\*가입→전시 생성→게시 단계별 수\*\*(1인 운영 증거). 질문 문장·비공개 원문·이메일은 반환하지 않는다.\

원 계획 그대로. 새 section 목록(W10)을 대상으로 분류하도록 맞춘다. Notion F03(작가 AI 인터뷰)은 P1이므로 만들지 않는다.\

\### W7 — 검증과 인계\

\- 전 구간 통합 테스트(모의 제공사)를 새 흐름으로: 가입 → 직접 로그인 → 홈 → 전시 2단계(임시저장·이어 쓰기) → 작품 등록·재정렬 → 해설·예상 Q&A 생성 → 검수·미리보기 정정·승인 → 게시 → 전시 QR → 소개 → 채팅(전시 전체/작품, 답 있음/없음) → 보완 요청 → 보완·재게시.\

\## 6. 순서와 줄일 수 있는 범위\
\
마감은 2026-11-15 아침이다. 전부 들어가지 않을 수 있다.\
\
1\. \*\*D0\*\* 문서 병합(ID 충돌 해소) — 이후 모든 묶음의 근거.\
2\. \*\*W10\*\* 입력 계약 — 프런트가 가장 먼저 붙는 계약이고 W11·W12의 선행.\
3\. \*\*W9\*\* 직접 가입 — 작고 독립적이다. Q-09 답을 기다리는 동안 W10을 진행한다.\
4\. \*\*W11\*\* 예상 Q&A·검수 → \*\*W12\*\* 공개·관람.\
5\. \*\*W8 잔여\*\* 중 가입·검수 대기 안내와 보완 질문 요약 → \*\*W6\*\*.\
6\. \*\*W2\*\* → Alt 전사 가져오기 → 실패 분류·브리핑.\
7\. \*\*W7\*\*은 묶음마다 누적하고 마지막에 인계 문서를 정리.\
\
트랙 2 평가는 운영 자동화에 있다. 시간이 모자라면 5번을 4번의 미리보기 정정·전시 전체 Q&A보다 먼저 한다. 줄이는 순서: 미리보기 정정 → 전시 전체 예상 Q&A → Alt → 브리핑 → W2. 줄인 것은 플래그를 끈 채 남기고 인계 문서에 "미구현"으로 적는다. 구현하지 않은 기능을 완료로 표시하지 않는다.\
