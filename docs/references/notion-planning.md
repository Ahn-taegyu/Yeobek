<b>우선순위 조정 제안 3가지</b>

1. 작품 인식 방식 4개(숫자·QR·NFC·위치) 중 MVP에는 <b>숫자 + QR 2개만</b> 남긴다. NFC·위치인식은 하드웨어와 현장 설치가 필요해 출시 버전으로 미룬다.
2. 이벤트 로그 저장은 MVP에서 <b>제외</b>하고 출시 버전에서 데이터 수집과 함께 넣는다. MVP 지표는 동적 QR 스캔 수와 작가 인터뷰로 확인한다.
3. AI 인터뷰는 MVP에 고정 질문 4개 + 꼬리 질문 1회의 텍스트 버전으로 넣는다(5-1 참고). 음성 답변과 여러 번 이어지는 대화형은 <b>제외</b>하고 출시 버전에서 넣는다. 인터뷰는 SoundArt Studio 등 경쟁사에 없는 핵심 차별점이다.

<toggle heading="h3">
작가 정보 입력 설계: 고정 질문 + 대화형 AI 인터뷰

<callout icon="🎙️" color="purple_bg">
작가에게 글을 쓰게 하지 않고, <b>짧게 답하게 한 뒤 AI가 해설로 엮는다.</b> 질문 순서와 종료는 프로그램이 정하고, AI는 "답이 충분한가 판단 + 부족하면 꼬리 질문 1회"만 맡는다. MVP에는 이 절충안(고정 질문 + 꼬리 질문 1회, 텍스트)을 넣는다. 기본안보다 약 반나절 추가 개발이다.
</callout>

<b>입력 흐름</b>

1. 전시 만들기: 전시 공통 질문 2\~3개에 한 번만 답한다.
2. 작품 사진 업로드 (선택: 작가노트·인스타 캡션·도록 붙여넣기)
3. 작품별 고정 질문 4개를 순서대로 묻는다. 붙여넣은 자료에 이미 답이 있는 질문은 건너뛴다.
4. 답마다 AI가 충분 여부를 판단하고, 부족하면 꼬리 질문을 한 번만 한다.
5. 4개가 끝나면 AI가 답만 근거로 해설 초안을 쓰고, 문장마다 근거 질문 번호를 붙인다.
6. 작가가 검수 화면에서 근거를 보며 수정·승인한다.

<b>기본 질문지</b>

| 구분 | 질문 | 뽑아내는 것 |
| --- | --- | --- |
| 전시 공통 | 주로 어떤 작업을 해오셨나요? | 작가 세계 |
| 전시 공통 | 이번 전시의 주제나 제목에 담은 뜻은? | 전시 주제 |
| 전시 공통 | 관람객이 전시를 보고 무엇을 느끼거나 가져가면 좋겠나요? | 전시 메시지 |
| 작품별 Q1 | 이 작품을 한 문장으로 소개한다면? | 주제 |
| 작품별 Q2 | 만들게 된 계기나 그때의 생각·감정은? | 의도 |
| 작품별 Q3 | 재료나 기법에서 특별히 신경 쓴 부분은? | 표현 방식 |
| 작품별 Q4 | 관람객이 꼭 봐줬으면 하는 부분은? | 감상 포인트 |

<b>대화형 인터뷰를 "잘 묻게" 만드는 규칙</b>

| 문제 | 해결 방법 |
| --- | --- |
| 언제 멈출지 모름 (너무 짧거나 끝없이 물음) | 질문 수는 프로그램이 고정(작품당 4개), 꼬리 질문은 질문당 최대 1회. AI는 종료를 결정하지 않는다 |
| 유도 질문 ("외로움을 표현하신 거죠?") | 꼬리 질문에 AI의 해석·감정 단어를 넣지 않도록 금지. "어떤 장면이나 순간이 떠올랐나요?"처럼 열린 질문만 허용 |
| 항목 누락 (기법·감상 포인트를 안 물음) | 항목을 고정 질문으로 못 박아 두고 하나씩 체크 |
| 단답형 작가 | "충분" 기준을 명시: 계기·장면·감정·구체적 대상 중 하나 이상. 없으면 구체적인 꼬리 질문 |
| 답하기 어려운 질문 | 꼬리 질문은 예/아니오가 아닌 한 문장으로 답할 수 있는 크기. "모르겠어요"는 그대로 넘어간다 |
| 작품과 동떨어진 질문 | 작품 사진을 함께 보내서 꼬리 질문이 화면 속 요소(색·형태·재료)를 가리킬 수 있게 한다. 단, 해석은 넣지 않음 |
| AI가 지어낸 해설 | 정리 단계에서 "답에 없는 의도·감정 추가 금지" + 문장마다 \[Q2\] 같은 근거 표시. 근거 없는 문장은 검수 화면에서 강조 |

<toggle>
답변 판단 지시문 (예시)

```javascript
너는 미술 작품 인터뷰를 돕는 조수야.
지금 질문: "{질문}"
작가의 답: "{답}"
이 질문에 이미 꼬리 질문을 했는가: {예/아니오}

규칙:
- 답에 계기, 장면, 감정, 구체적 대상 중 하나 이상이 있으면 "충분"
- 없으면 "부족"으로 판단하고, 한 문장으로 답할 수 있는 꼬리 질문을 하나 만들어
- 꼬리 질문에 네 해석이나 감정 단어를 넣지 마. 유도 질문 금지
- 작가가 "모르겠다"고 하거나, 이미 꼬리 질문을 했으면 무조건 "충분"

이 형식으로만 답해:
{"판단": "충분" 또는 "부족", "꼬리질문": "..."}
```
</toggle>

- <b>갤러리 반복 매출:</b> 대관 갤러리 한 곳이 매달 새 전시를 연다. 구독 갤러리가 늘면 매출이 쌓이는 구조다.
- <b>관람객 바이럴:</b> 전시가 늘수록 관람객 노출이 늘고, 그중 작가·미대생이 새 고객이 된다.
- <b>외국인 관광객 증가:</b> 2025년 방한객은 역대 최다인 1,893만 7천 명이었다 ([파이낸셜뉴스](https://www.fnnews.com/news/202602241111042813)). 야놀자리서치는 2026년 2,036만 명을 예측했다 ([헤럴드경제](https://www.heraldk.com/article/2025123017542262712)). 다국어 해설 수요가 늘어난다.

| TTS API | 해설 음성 | 클로바 보이스·ElevenLabs·OpenAI TTS 한국어 품질 비교 필요 | 글자 수·음성 분량 기반 |
| Alt·라이너 | 해커톤 파트너 도구 | Alt는 녹음 전사·요약 가져오기, 라이너는 LLM 응답·검색 API | 행사 크레딧 제공 범위 확인 필요 |
| Zapier·Make·n8n | 도구 간 연결 | 가입·결제·전시 종료 같은 이벤트로 다음 작업 실행 | n8n은 직접 설치 시 무료 |

✅ 검증 계획 및 다음 할 일

<callout icon="💡" color="blue_bg">
가장 먼저 확인할 것은 기술이 아니라 \*\*"작가가 실제로 쓰고, 돈을 낼까"\*\*다. 코드를 많이 짜기 전에 인터뷰와 수동 파일럿으로 확인한다.
</callout>

<toggle heading="h3">
4단계 검증

| 단계 | 방법 | 통과 기준 | 기간 |
| --- | --- | --- | --- |
| ① 문제 검증 | 개인전 경험 작가 10명 인터뷰 | 6명 이상이 "해설이 있으면 좋겠다 + 직접 만들기는 부담" | 2주 |
| ② 수동 파일럿 (오즈의 마법사) | Claude로 해설 작성 + TTS 파일 + 노션/구글사이트 + QR로 작가 2명 전시에 수작업 적용 | 관람객 QR 접속 30% 이상 | 2\~3주 |
| ③ 가격 검증 | 파일럿 작가에게 "다음 전시에 39,000원이면 쓰겠나요?" → 사전 결제·예약 요청 | 3명 중 1명 이상 사전 결제 | 1주 |
| ④ MVP 개발·테스트 | MVP PRD 범위 개발 후 작가 3\~5명 | MVP 성공 지표 달성 | 6\~8주 |

②를 코드 없이 하는 이유: 관람객이 QR을 찍지 않는다면 앱을 아무리 잘 만들어도 소용없기 때문이다. 반대로 수작업 버전도 반응이 있으면 해커톤·경진대회에서 "실제 데이터"로 쓸 수 있다.
</toggle>

작가 인터뷰 질문 (초안)

2. 관람객에게 작품을 설명하기 위해 지금 무엇을 하고 있나요? (캡션, 작가노트, 직접 상주 등)

4. 관람객이 작품을 오해하거나 놓친다고 느낀 부분이 있나요?
5. 작품마다 꼭 전하고 싶은 이야기(계기, 재료, 기법)는 지금 어디에 정리해 두셨나요?
6. 작품 설명은 말로 하는 것과 글로 쓰는 것 중 어느 쪽이 편한가요? 작품 한 점에 몇 분 정도 이야기할 수 있나요?
7. 작품 이야기 중 관람객에게 공개하고 싶지 않은 내용이 있나요?
8. 관람객의 질문이나 반응을 알 수 있다면, 다음 작품이나 전시에 어떻게 반영하고 싶으세요?
