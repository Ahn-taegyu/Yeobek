# 확정한 경험과 제안한 구현

**해설·질문·추가 설명을 하나의 채팅에서 처리하고 입력과 출력을 독립 선택한다.** 이것은 [사용자 요구](../references/user-chat-interaction.md)다. 아래 녹음·전송·상태 규칙은 이를 구현하기 위한 설계 제안이며 앱 구현 완료를 뜻하지 않는다.

작가용 입력·검수는 [D-011](../decisions/D-011-knowledge-and-screens.md)에 따라 홈·공통 정보와 AI 참고 정보 확인을 보완한다. 관람객에게 별도 '해설 보기'와 '질문하기' 화면으로 오가도록 요구하지 않는다. 작품 목록은 채팅의 배경 영역에 두고 작품 정보는 보조 화면/시트로 제공한다. 작품 정보를 열어도 질문과 해설은 같은 채팅에서 이어진다. 그리드+상단 선택 칩은 초기 배치 제안이다.

후속 설계를 위한 화면·버튼·상태는 [SC-V01~V06](screen-spec.md), 업무 계약은 [기능명세 v1.0 BR-08~14](functional-spec.md), 검증은 [UC-06~12](user-scenarios.md)를 사용한다. 작품 선택만으로 자동 질문을 보내지 않고 `해설 보기`나 명시적 번호/해설 요청으로 시작한다는 동작은 이번 상세 제안이다.

# 네 가지 조합

| 입력 모드 | 출력 모드 | 동작 |
| --- | --- | --- |
| 텍스트 | 텍스트 | 입력한 요청의 답을 채팅 글로 표시 |
| 텍스트 | 음성 | 입력한 요청의 답을 음성으로 전달 |
| 음성 | 텍스트 | 발화를 인식해 요청 처리, 답은 글로 표시하고 자동 낭독하지 않음 |
| 음성 | 음성 | 발화를 인식해 요청 처리, 답을 음성으로 전달 |

input_mode와 output_mode를 서로 다른 값으로 저장한다. 입력 선택이 출력 선택을 변경하지 않는다. 둘 다 바꾸더라도 같은 채팅·현재 작품·대화 기록을 유지한다. 음성 모드에서도 인식문·답변 글·출처를 펼쳐 확인할 수 있도록 제안하지만, 음성과 글을 항상 동시에 강제 표시하는 것은 아니다.

# 대화 예시

1. 관람객이 전시 QR로 진입해 온보딩을 마치고 작품 목록 배경의 채팅을 연다.
2. 입력=음성, 출력=텍스트에서 “18번 작품 설명해줘.”라고 말한다.
3. 도슨트는 해당 전시의 18번을 찾아 현재 작품으로 설정하고 승인된 해설을 같은 채팅에 글로 표시한다.
4. 관람객이 입력만 텍스트로 바꾸고 “오른쪽 위에 그려진 건 뭐야?”라고 입력한다.
5. 현재 작품과 해당 부위의 승인 설명을 확인해 답한다. 대상이 불명확하면 “오른쪽 위의 둥근 형태를 말씀하시나요?”처럼 관측/근거가 있는 대상만 확인한다. 확인할 단서가 전혀 없으면 위치·모양 설명을 요청한다.
6. 출력만 음성으로 바꾸면 이후 응답은 음성으로 전달된다. 기존 답변을 듣는 동작은 그 답변의 낭독이며 새 질문이나 다른 해석을 만들지 않는다.
7. “19번 작품도 설명해줘.”를 처리하면 같은 채팅에서 현재 작품이 바뀐다. 18번 대화 기록은 남지만 새 답의 근거로 무분별하게 섞지 않는다.

# 작품과 부위 문맥

- 작품 번호는 전시 범위 안에서 해석한다. '18번/십팔 번' 같은 표기를 정규화한다.
- 우선순위 제안: 이번 메시지의 명시적 작품 번호·선택 → 현재 채팅 작품. 현재 작품이 없거나 후보가 여럿이면 되묻는다.
- 존재하지 않거나 비공개인 작품을 요청하면 기존 현재 작품을 임의 변경하지 않는다.
- 작품 정보 화면의 탐색 대상과 현재 질문 대상을 분리한다. 카드 정보 열기/닫기는 현재 작품·작성 글·모드를 유지하고 `이 작품으로 질문`으로만 선택한다.
- 선택된 작품은 채팅 상단 칩에 표시하는 안이다. 입력창 mention은 대안이며 둘 다 구현할 필수 조건이 아니다. 칩을 해제하면 작품·부위만 비우고 기록을 유지한다.
- 명시적 번호가 없는 `이 작품`은 표시된 선택을 사용한다. `19번`이 명시되면 이전 상단의 18번보다 우선하되 서버 공개 확인 후 최신 문맥 순번에 맞게 갱신한다.
- '이 작품'은 현재 확인한 작품을 가리키며, '이 부분'은 말·글에서 특정한 위치/모양 또는 직전 확인한 대상을 가리킨다. 카메라나 위치 센서가 없는데 실물 지시를 알았다고 가정하지 않는다.
- 작품 전환 시 활성 부위 문맥을 초기화한다. 채팅 기록 자체는 지우지 않는다.
- 답변 생성 시작 시 작품 ID·공개 버전·질문을 고정한다. 처리 중 다른 작품을 선택해도 도착한 답은 원래 작품 메시지에 붙인다.
- 요청에 문맥 변경 순번을 연결해 늦은 작품 해석이 최신 선택을 되돌리지 않게 한다. 응답 도착 시 현재 출력 모드를 적용하지만 작품 문맥이 달라졌으면 자동 낭독하지 않는다. 한 채팅의 답변 생성 요청은 1개씩 처리한다.
- 다른 전시로 이동하면 명시적으로 전시 문맥을 바꾸고 기존 전시의 근거를 자동 혼입하지 않는다. v1.0 상세안은 같은 탭에서 전시별 sessionStorage 기록을 분리하고 복귀 시 공개 버전을 검증하는 방식이다. 새 탭/기기 간 복원은 보장하지 않는다.

# 해설과 답변의 근거

“18번 설명해줘”는 검수된 해설을 반환하는 기본 경로다. 꼬리 질문·요약 요청은 해당 전시에서 공개 승인한 작가 공통·전시 공통·작품 근거에서 답변을 생성한다. 내부 위키 원본 전체를 검색하지 않는다. 실시간 생성 답변마다 작가의 사전 승인을 요구하지 않으며 출처·불확실성을 표시한다.

“그려진 게 무엇인가”를 처리하려면 그 부위의 작가 설명/시각 설명 또는 실제 이미지 분석 결과가 필요하다. 언어로 위치를 지정했다는 사실만으로 AI가 그림을 본 것은 아니다. 텍스트 근거에 없고 이미지 분석도 검증하지 않았다면 확인할 수 없다고 답한다.

이미지 처리에는 [D-007](../decisions/D-007-visual-reference.md)을 적용한다. 승인 이미지 분석을 추가하더라도 '이미지에서 보이는 요소'와 '작가가 말한 의도'를 분리한다.

# 녹음과 음성 출력의 구현 기준

최초 [D-008](../decisions/D-008-technology-stack.md)의 MediaRecorder·녹음 확인 흐름을 유지한다. 최신 [D-010](../decisions/D-010-practical-stack.md)은 OpenAI STT + Typecast TTS를 권고하며 새 제공사 선택은 미확정이다. 한국어, 기본 text/text, 30초/3MB 녹음과 인식문 확인 후 전송으로 시작한다. 세부 상한·음성 모델 종료 예정·실기기 확인은 [기술 스택](technology-stack.md)을 따른다.

- 녹음 시작/종료 후 전송하는 방식으로 음성 입력을 제공한다. 항상 듣기·동시 말하기·자동 발화 감지는 확정 요건이 아니다.
- 음성 인식 결과는 같은 사용자 메시지의 텍스트 표현이다. 오인식은 확인·수정·재전송할 수 있다. 인식 중간 결과를 여러 질문으로 전송하지 않는다.
- 새 녹음을 시작할 때 도슨트 재생을 일시정지해 자기 음성을 다시 입력하는 상황을 줄인다. 입력/출력 모드 값은 바꾸지 않는다.
- 입력 모드를 바꿀 때 미전송 녹음을 자동 제출하지 않는다. 취소/확인 경로를 둔다.
- 출력 모드를 바꿔도 새 답을 생성하지 않는다. 음성→텍스트 전환은 현재 재생을 멈추고 같은 답변을 보여준다. 텍스트→음성은 같은 답변 낭독을 요청할 수 있다.
- 응답 글을 기준으로 음성을 만들고 메시지 ID·글 버전/해시에 연결한다. 고정 해설은 준비된 음성을 재사용할 수 있고, 새 Q&A는 해당 답변의 음성을 생성한다.
- 음성 출력 실패 시 글을 확인하고 낭독만 재시도할 수 있게 한다. 출력 선호는 음성으로 유지한다.
- 대화용 인식문/문맥 유지와 P2 관람 분석은 별개다. 원음 장기 저장·관람객 계정은 이 요구에서 자동 도출하지 않는다.

# 수용 시나리오

1. 같은 채팅에서 네 입력×출력 조합 모두 해설 요청과 후속 질문이 동작한다.
2. 음성 입력→텍스트 출력에서 답이 자동 낭독되지 않는다. 텍스트 입력→음성 출력도 가능하다.
3. 모드 전환만으로 요청 중복·새 채팅 생성·작품 문맥 소실이 일어나지 않는다.
4. “18번 설명해줘”→“이 작품 오른쪽 위에는 뭐가 있어?”가 같은 작품 문맥으로 이어진다.
5. '이 부분'만으로 대상이 특정되지 않으면 추측 대신 되묻는다.
6. 19번으로 전환해도 기록은 남고 활성 작품/부위만 갱신된다.
7. 마이크 거부·무음·인식 실패·통신 오류 때 텍스트 입력으로 이어갈 수 있다. 이때 출력 모드는 유지한다.
8. 늦게 도착한 답과 음성이 다른 작품/메시지에 붙지 않는다.
9. 질문 원문을 바꾸지 않은 채 출력만 전환해도 답변 의미와 출처가 일치한다.
10. 온보딩·작품 정보·배경 목록을 오가도 같은 전시의 대화·입력·독립 모드를 보존한다. 정보 탐색만으로 질문 대상이 바뀌지 않는다.
11. 상단 선택 표시·서버가 확인한 작품·메시지 대상이 일치하고 선택 해제 후 이전 작품을 묵시적으로 재사용하지 않는다.
