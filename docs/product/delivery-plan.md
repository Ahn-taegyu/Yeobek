# 일정 기준과 완료 목표

사용자는 **사전 개발 가능**을 확인했다. 11/13 현재 저장소에서 제품 앱 구현은 확인되지 않았으므로 금요일부터의 남은 작업을 아래처럼 다시 배치한다. 과거 목요일 일정은 완료 기록이 아니다. 공식 행사는 **11/14 16:40~11/15 06:30(KST)**이며 정확한 제출 시각은 아직 미확인이다. **팀 내부 개발 완료 목표는 일요일 04:30**, 02:00부터 새 기능을 넣지 않는다. 이 시각은 공식 제출 마감이 아닌 우리 계획이다. 기획 담당은 공지된 실제 제출 시각을 확인하고 더 빠르면 마지막 검증 구간을 앞당긴다.[^direction][^event]

기획 1명·프런트 보조 1명·디자인 1명·핵심 개발자 1명이다. 핵심 개발자가 프런트·백엔드·AI를 맡으므로 아래 계획은 **핵심 개발 약 26~30시간**을 가정한 공격적인 일정이다. 나머지 세 명의 작업을 핵심 개발 3명 분량으로 계산하지 않는다. 금요일 야간 휴식과 토요일 행사 전 휴식을 확보하며, 일정은 팀의 실제 작업 가능 시간에 맞춰 조정한다. 11/13 내부 지식·화면 보완으로 기존 24~28시간보다 2시간 늘린 추정이며 실측이 아니다. 온보딩·작품 정보 UI는 프런트 보조가 병행하고 별도 위키 편집기·복수 목록 배치 구현은 넣지 않는다.

# 개발 순서와 완료 기준

**처음부터 관리자 전체를 만든 뒤 채팅을 시작하지 않는다. 먼저 작품 1점으로 관람객의 끝까지 이어지는 흐름을 시험한다.** 아래 단계는 착수 순서다. Features Base의 선행 조건은 최종 완료 의존성이므로 개발용 seed/mock으로 UI를 먼저 작업할 수 있다.

| 단계 | 핵심 개발 예상 | 구현 | 통과 기준 |
| --- | --- | --- | --- |
| 0. 실행 환경·위험 확인 | 2시간 | Next·Supabase 기본 연결, HTTPS 미리보기, OpenAI STT/Q&A·선택 TTS 각 1회 | 휴대폰 녹음→한국어 인식, 지정 글→재생 성공. 모델 접근 불가면 즉시 해결 대상으로 전환 |
| 1. 한 작품 채팅 | 4시간 | 공개 seed 1점, 온보딩·목록 배경·작품 정보·선택 표시, 한 채팅·독립 모드·답변/음성 ID | “18번 설명해줘”와 네 조합 동작. Q&A 실제 호출과 mock을 구분 |
| 2. 작가 입력·권한 | 5시간 | 작가 로그인·홈·공통 정보, 전시/작품 입력, 내부 문서/관계, 사진/PDF·발췌·출처 | 새 작품 저장·새로고침 복구, 다른 작가 계정의 조회/수정 차단 |
| 3. 검수·게시 | 4시간 | 해설 생성 계약, 공개 근거 선택·수정·승인, 승인본 TTS, 게시/중지·QR | 새 입력으로 기본 해설을 실제 음성까지 준비하고 게시. 새 초안이 기존 공개본에 섞이지 않음 |

| 5. 검증·수정·시연 | 7~11시간 | 모드/오류·권한·휴대폰·두 번째 전시·리허설 | 필수 수용 기준 통과, 배포 주소·QR·발표 자료·백업 준비 |

실제 음성 시험을 첫 단계에 배치한다. 단일 채팅·글/음성 분리는 앱 전체에 영향을 주므로 마지막에 추가하지 않는다. STT와 TTS만 확인해도 근거 기반 Q&A 품질이나 Liner 초안 생성이 검증됐다는 뜻은 아니다.

**추가 조사에 따른 제안:** 단계 0에서 접근 가능한 대안 한 개와 기존 음성을 30~45분 비교하고 한 목소리를 고정한다. [청취 평가안](../research/voice-options.md). 이 시간은 별도 여유 시간이 생겼다는 뜻이 아니며 전체 단계 0 예산과 작업량을 조정한다. 기획 담당은 실제 파일 크기와 선택 플랜/키 조건을 확인한다. Render 지원 확인 대기는 제거했다. 새 모델/호스팅은 [D-010](../decisions/D-010-practical-stack.md)의 권고와 검증 조건으로 진행한다.

# 일정이 밀릴 때의 순서

1. 장식·애니메이션, 관리자 화면 분리, QR 인쇄 디자인, 채팅 타이핑 효과를 줄인다.
2. 기본 해설/답변 길이와 시연 자료를 줄여 생성·검수 시간을 줄인다. 핵심 입력·검수·게시 흐름은 남긴다.
3. 이미 제외한 OCR·이미지 분석·파트너 추가 통합을 다시 넣지 않는다.
4. 음성 모델 접근 실패는 오늘 해결한다. 라이너 키는 행사 직후 해결한다. UI 변경 없이 어댑터만 수정하고, 확인되지 않은 모델/제공사를 작동하는 대안으로 표시하지 않는다.
5. 라이너가 제공되지 않거나 핵심 호출이 계속 실패하면 주최 측에 사용 가능한 파트너 경로를 확인해야 한다. OpenAI만 동작하는 시연은 이 트랙의 API 조건을 충족했다고 발표하지 않는다.

독립 모드 네 조합, 승인/공개 범위, 실제 파트너 호출은 완료 조건이다. 텍스트 복구 기능은 음성 MVP를 완료한 것으로 대신할 수 없다.

# 시연 흐름

작품 자료 입력 → 생성 초안 수정/검수 → 실제 음성 준비·게시 → QR → 음성으로 “18번 작품 설명해줘”, 글로 답변 → 글로 부위 질문, 음성으로 답변 → 모호한 질문 되묻기 → 작품 전환 → 공개 중지. 나머지 두 모드 조합은 리허설에서 반드시 확인한다.
