### 업로드 파일 읽기 방식

- 텍스트가 있는 PDF는 서버에서 글자만 뽑는다. AI 비용이 없다.
- 스캔 PDF와 참고 이미지는 AI 모델이 읽는다. Liner가 이미지·PDF 입력을 지원하는지 먼저 확인하고, 안 되면 기존 비교 후보(OpenAI 등)를 쓴다.
- 결과는 W2 정리 후보로만 들어간다. 작가가 확인해 적용해야 근거가 된다.
- 비용 경계: 파일 해시당 1회, 파일당 최대 20쪽(정책값), 작가 일일 작업 한도에 포함, "여운 학습시키기"를 누를 때만 외부 전송.
- 키 당일 실측 전까지는 모의 결과로만 검증한다.

**지시문 수정은 버리지 않는다.** 사용자가 A4에서 "기본 작품 소개만 직접 수정, 나머지는 지시문"이라고 정했고 디자인 화면도 있다. 대신 기존 생성 작업에 지시문을 덧붙여 새 작업본을 만드는 가장 단순한 방식으로 만든다.

### AI 사용량을 줄이는 작업 방식

- 전체 lint·typecheck·test·build는 로컬에서 반복하지 않고 **PR CI로 한 번** 확인한다. 로컬은 고친 부분의 좁은 검사만 한다.
- 긴 기획 문서를 통째로 다시 읽지 않는다. 묶음에 해당하는 절만 `knowledge.py search`나 `rg`로 찾아 읽는다.
- 보고는 묶음마다 5줄 이내로 쓴다.
- 실제 외부 AI·TTS 호출은 하지 않는다(모의 모드). 실물 확인은 키 당일 점검으로 미룬다.

## 디자인이 아직 없는 화면 (프런트 범위 밖, 결정 필요)

- **이메일 가입·로그인·인증 안내:** Figma 시작 화면에는 소셜 버튼만 있다. 보조 작업자가 기존 로그인 화면 스타일로 최소 폼을 만든다.
- **기본 해설 원고 검수·승인 화면:** A7에서 "별도 화면"으로 정했지만 디자인이 없다.
- **게시 체크리스트·게시·중지 화면:** 디자인이 없다.

디자인이 없으면 시연에서 작가가 직접 게시할 수 없다. 시연은 B의 `db:seed:demo`로 게시된 전시를 쓰고, 두 화면은 디자이너에게 요청한다. 디자인이 오면 서버 API는 이미 있으니 프런트만 붙이면 된다.
